# 论文写作要求与团队工作流

> 本文档分为两部分：课程硬性要求，以及团队采用的“先中文全文、后分工、再英文定稿”工作流。课程要求以 [`PROJECT_REQUIREMENTS.md`](../PROJECT_REQUIREMENTS.md) 第 9 节为准。

## 1. 课程硬性要求

- 以 PDF 提交。
- 总篇幅约为每名成员 4,000 English words，且不应明显超过。
- 每个章节或小节的标题后标明主要作者，以便分别评分。
- 不得使用大学 Logo。
- 报告开头必须包含公开代码仓库 URL 和额外依赖。
- 报告 PDF 本身不得上传到公开代码仓库。
- 必须介绍团队开发过的全部模型，并用系统实验说明最终模型的选择依据。
- 一级章节必须依次为：
  1. Introduction
  2. Background
  3. Project Planning
  4. Methods
  5. Training
  6. Experiments and Results
  7. Conclusion

各章的课程要求如下：

- **Introduction**：简要说明问题、价值和挑战。
- **Background**：详细介绍任务，并概述考虑过的强化学习方法。
- **Project Planning**：说明团队组织、时间规划、子任务分配、协作方式和深度学习训练硬件。
- **Methods**：解释并论证关键设计选择、待比较变体、性能指标和系统测试方法，并引用相关文献。
- **Training**：描述训练过程，以及用于改善或加速训练的技巧。
- **Experiments and Results**：作为全文重点，系统评价每项设计或实现变化带来的改善、无改善或失败。
- **Conclusion**：总结发现，并说明若有更多时间将如何改进 Agent 和游戏设置。

## 2. 写作入口与文件角色

| 文件 | 角色 | 当前使用规则 |
|---|---|---|
| `main_outline_template copy.tex` | 只读框架参考 | 保持不变，不在其中写论文正文 |
| `main_zh.tex` | 中文事实基线稿 | 已由三个完整证据输入包生成初稿；团队审计后冻结并继续保留 |
| `main_en.tex` | 英文翻译与审校稿 | 仅在中文内容冻结、主笔分配完成后创建 |
| `main.tex` | 最终英文提交入口 | 英文定稿前不得宣称为最终稿；提交前与 `main_en.tex` 完整同步 |

### 写作风格指南

编辑中文稿、英文稿或队员提供的论文段落前，请先阅读[论文写作风格指南](WRITING_STYLE.md)。该指南统一报告口吻、术语解释、句子表达和章节职责。课程硬性要求与事实、证据规则仍以本文件、`PROJECT_REQUIREMENTS.md` 和可追溯的项目证据为准；风格调整不得改变数值、评估协议、证据状态或结论强度。

当前写作入口已满足：Die Hardest 个人证据档案、Q-learning/CNN 整合报告及原始结果、Rainbow 时间线与 run/CSV 记录共同构成三个完整证据输入包。`main_zh.tex` 已进入完整初稿与团队核验阶段；这不等于内容已冻结。

## 3. 阶段 0：证据准备

必须先收齐三个完整证据输入包。输入包不强制采用相同格式或证据标签，但合起来必须覆盖：

- 方法与设计动机；
- 实验和训练流程；
- 主要结果及其协议；
- 失败、无改善和未运行内容；
- 已知限制与不能支持的结论；
- 可追溯的源码、配置、checkpoint、run 或结果路径。

个人说明是内部证据档案，可以保留真实技术贡献和来源。论文初稿暂缓主笔分配，不意味着删除证据档案中的归属信息。

## 4. 阶段 1：完整中文稿

三个输入包齐备后，按 `REPORT_OUTLINE.md` 的研究问题和七章结构统一重写全文：

- 不把三份说明直接拼接为三个成员章节；
- 封面保留三名团队成员姓名；
- 正文统一使用团队视角，暂不写个人技术贡献；
- 每个章节和小节保留可见的“主要作者”空白栏；
- 所有数字必须追溯至结果文件，不能用训练 reward 替代正式游戏指标；
- `not_reported`、`unrun` 和 `not_comparable` 不得改写为零或正式比较结果；
- 新增引用必须先核验来源，不得凭记忆生成 BibTeX。

中文内容只有同时满足以下条件才能冻结：

- 摘要、七个一级章节和必要附录均为完整正文；
- 图、表、公式、引用和交叉引用均已落位；
- 定量结果、实验协议和证据状态已经核对；
- 局限和未完成实验已明确披露；
- 不再包含实质性的 `\todoitem`、写作提示或待确认主张。

## 5. 阶段 2：冻结后分工

中文内容冻结后、英文翻译前执行一次统一分工：

1. 根据技术经验和实际贡献为 section/subsection 匹配主笔。
2. 根据预计英文篇幅调整小节，使三人的负责内容接近每人 4,000 English words。
3. 填写所有主要作者栏。
4. 在 Project Planning 的贡献表中补充责任人、协作者、共享成果和证据路径。
5. 每位主笔对所分配内容进行实质性复核，并承担最终文字和答辩责任。

主笔身份、技术贡献和团队署名是不同概念，不得相互替代。除 Project Planning 的明确贡献记录外，技术叙述继续使用团队视角。

## 6. 阶段 3：英文翻译与审校

- 以冻结后的 `main_zh.tex` 创建结构一一对应的 `main_en.tex`。
- 采用忠实的学术化改写，而非逐句直译。
- 可以调整英语句式，但不得改变数值、实验状态、比较边界、因果强度、引用关系或作者标签。
- Codex 可生成统一风格的英文初稿；各主笔复核负责章节；最后进行全篇术语和论证一致性编辑。
- 中文稿是事实基线：事实或结构修改必须同步到中英文两稿；纯英文措辞润色只修改英文稿。

## 7. 实验与引用写作规则

每个实验单元交代：问题或假设、唯一变化、训练/评估数据量、结果与波动、能够支持的结论、不能支持的结论和后续决策。

- 每个 training seed 单独报告，再给跨 seed 均值和标准差。
- 相同世界的父子模型比较优先使用配对统计。
- 不把一个 checkpoint 的 100 局当成 100 次独立训练。
- 单 Agent 场景报告金币、效率和死亡，不使用“胜率”。
- 训练 loss 和 shaped reward 不能替代正式游戏得分。
- 截止日期后的实验必须区分“已提交参赛版本”和“后续实验版本”。
- 无法程序化核验的文献使用显式 `[CITATION NEEDED]` 占位，不得虚构引用。

## 8. 最终验收

- 使用 XeLaTeX 分别编译 `main_zh.tex`、`main_en.tex` 和 `main.tex`。
- 逐项核对中英文的章节、数字、图表、引用、术语、证据边界和作者标签。
- 按主笔负责的英文 section/subsection 统计词数，检查每人约 4,000 words。
- 确认每个章节和小节均有真实主要作者，且与贡献表和内部证据不冲突。
- 英文定稿后，将 `main_en.tex` 完整同步到 `main.tex`，并用内容比较确认二者一致。
- 删除全部写作提示和占位符，确认公开仓库 URL、依赖、硬件、seed、checkpoint 和模型标识。
- 运行 LaTeX 编译、链接检查与 `git diff --check`。
