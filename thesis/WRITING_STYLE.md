# 论文写作风格指南

本指南适用于本论文的中文稿、英文稿，以及队员提供的相关报告段落。它只统一表达方式，不替代课程要求、项目事实基线或证据规则。遇到冲突时，以 [`Writing_Instruction.md`](Writing_Instruction.md)、[`PROJECT_REQUIREMENTS.md`](../PROJECT_REQUIREMENTS.md) 和可追溯的项目证据为准。

## 写作目标

让读者看清我们遇到了什么问题、为什么选择某种做法、实现具体做了什么，以及实验结果能支持什么判断。整体语气像学生团队对项目的清楚复盘：自然、具体、克制。避免公文套话、空泛总结和随意口语。

叙述团队作出的选择和采取的行动时，可以自然使用“我们”。描述代码行为、配置、指标和观察结果时，直接陈述事实，不必每句都加“我们”。不要把方法写成开发日志，也不要只罗列做过的步骤。

## 句子与术语

- 每句话尽量围绕一个主要关系展开。条件、原因和结果挤在一起时，拆成两句，并明确它们之间的关系。
- 少用分号。意思可以独立成立时用句号拆开，关系紧密时用逗号或连接词。
- 首次出现的专门说法要就地解释它在本项目中具体指什么。优先写出实际检查、计算或比较的对象，不要只用“确定性打破平局”“目标延续”等压缩标签代替解释。
- 解释算法字段时，说明字段读取了什么、如何得到取值，以及读者应如何理解取值。必要时给一个简短例子。候选特征只表示输入中提供了某种线索，不能写成模型已经学会了相应行为。
- 常见技术术语可以保留，但不要为了显得专业而堆叠缩写。模型正式名称、代码标识、特征 ID 和 API 符号按项目原样书写。
- 表格负责完整呈现数据。正文重点解释结果模式、比较条件和决策，避免逐项复述表格中已经清楚列出的数字。

中文和英文遵循相同的具体、可读、证据克制原则，但句法应符合各自语言习惯。英文稿应忠实保留事实和论证关系，按自然英语重写，不逐句照搬中文语序。

## 章节各自承担的内容

- **方法**说明设计目标、选择理由和实际运行方式。实现步骤要足以让读者理解方法如何工作。对效果尚未验证、比较无法归因或适用范围有限的分析，放到结果讨论或结论的局限部分，不要在操作说明中插入免责声明。必要的行为定义仍留在方法中，例如某个候选标记不代表该行为已经发生。
- **实验与结果**交代比较的问题、评估协议、观察到的结果和结果支持的判断。不同协议或不同来源的数据要分开解释，不把它们写成直接可比的结果。
- **结论与局限**总结证据实际说明了什么、还不能说明什么，并把尚待回答的问题连接到具体的后续实验。保留会影响读者判断的负结果、安全反例和结论边界。

无论放在哪一章，都不能把相关性写成因果，也不能让一个 checkpoint 的多局测试看起来像多次独立训练。数值、单位、样本量、协议、引用和结论强度应能追溯到来源。

## 修改示例

以下例子摘自本次修改所依据的改稿前版本和当前中文稿中的对应段落，展示本指南对应的实际编辑。示例用于说明写法，不是要求英文稿沿用中文句式。

### 把实现常量翻译成读者能理解的含义

**修改前：**“覆盖箱数以 $4\,\texttt{BOMB\_POWER}$ 归一化。”

**修改后：**“爆炸范围内的箱子数除以炸弹沿上下左右四个方向各自最多能覆盖的格子数之和。当前设置下，每个方向最多覆盖 3 格，共 12 格；遇墙或棋盘边界时，实际覆盖范围会缩短。”

修改后保留了归一化所表达的计算，同时解释分母代表什么，以及为什么实际爆炸范围可能更小。

### 把含糊的平局规则和历史字段写清楚

**修改前：**“距离相同时按坐标确定性打破平局。随后比较本步和上一步的目标坐标，判断目标是否延续。”

**修改后：**“若多个金币到当前位置的最短步数相同，程序先选横坐标 $x$ 较小的。如果横坐标相同，再选纵坐标 $y$ 较小。……本次选中的可达金币与上次决策选中同一格时记为 1，否则记为 0。”

修改后说明了比较顺序，也把“延续”落实为两次决策选中的金币坐标是否相同。遇到这样的术语，应给读者可核对的判断规则，而不是只换一个同样抽象的词。

### 把结论边界放在合适的位置

**修改前（方法段落）：**“因此，现有结果评价的是包含这组历史字段的整体表示，不能单独说明它们带来的性能变化。”

**修改后（结论的局限部分）：**“84 维输入整体参与了现有实验，尚不能判断新增的 14 个历史字段是否帮助模型识别目标切换或减少折返。”后文将这一边界连接到逐项移除历史特征的未来消融实验。

方法段落保留字段如何计算、为何设计这些字段。关于当前实验能否归因于这些字段的分析放到结论，并明确提出怎样的实验可以回答这个问题。这样的调整是章节职责的变化，不能借机删掉重要的证据边界。

## 编辑队员文本时的流程

1. **先核事实。** 标出每项主张对应的代码、配置、结果、引用或项目记录。核对数字、对象、比较协议和证据状态。来源不清时先询问作者，不用更流畅的措辞掩盖不确定性。
2. **再理顺论证。** 检查段落是否说明问题、设计选择、操作方式和观察结果之间的关系。把方法、结果和局限放到合适章节，补足读者理解术语所需的解释。
3. **最后润色表达。** 按本指南调整句子长度、连接方式和重复内容。写英文时采用自然英语表达，保持原文的事实和论证关系。
4. **复核改动边界。** 逐项确认数字、引用、比较条件和结论强度没有被无意改变。凡是会改变事实含义、因果解释、证据状态或结论强度的改动，交由该段作者确认后再定稿。
