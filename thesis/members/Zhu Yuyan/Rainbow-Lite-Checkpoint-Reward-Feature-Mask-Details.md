# Rainbow Lite：Checkpoint、Reward、Feature 与 Survival Mask 详细实验记录

> 整理日期：2026-09-27
> 作用：扩展 [`Rainbow-Lite-Experiment-Timeline.md`](Rainbow-Lite-Experiment-Timeline.md)，把 Rainbow Lite 的 checkpoint、feature、reward、mask、父模型、评估规模和结果对应起来。
> 证据优先级：`runs/**/summary.csv` 与 checkpoint metadata > 实验配置 > 研究总结。本文不把训练 reward 当成正式游戏表现，也不把不同协议的小样本结果组成公平排行榜。

## 1. 如何阅读本文

一个 Rainbow Lite checkpoint 的完整实验合同是：

```text
checkpoint
= learner/network
+ feature_id
+ reward_id
+ survival-mask version/mode
+ parent checkpoint / migration method
+ training task, seed and budget
+ frozen evaluation worlds and sample size
```

因此，只有其余条件固定时，结果差异才可以较强地归因于某个 reward、feature 或 mask。本文采用以下证据标签：

| 标签 | 含义 |
|---|---|
| `verified_raw` | 本仓库有 `summary.csv`、metadata 或逐局记录，可直接核对。 |
| `verified_summary` | 有研究日志或汇总，但本文没有从完整逐局记录重算。 |
| `diagnostic_only` | 只有 5–20 局局部诊断，或协议/父 checkpoint 与别的分支不一致。 |
| `implemented_not_evaluated` | 已有代码或配置，但没有找到可核验的完成评估。 |
| `planned_or_interrupted` | 只创建了配置、smoke test 或运行中断，不能报告性能数字。 |

百分率均按冻结评估局数计算。`长 WAIT` 与 `长往返` 是导航诊断，不等于所有 WAIT 或所有反向移动。Task 1/2 的“第一名率”没有对手，不作为选模依据。

## 2. 版本合同总表

### 2.1 Feature 版本

| 版本 | 正式 ID / 维度 | 相对父版本的具体变化 | 预期解决的问题 |
|---|---|---|---|
| continuous-v2 | 84-D | 历史增强连续向量；旧 Rainbow 算法/表示对照 | 判断 Rainbow learner 在旧表示上是否能学会 Task 1 |
| continuous-v3 | 旧安全增强分支 | 改变安全相关字段及尺度 | 检查更显式安全表示是否改善 Task 2 |
| continuous-v4 | 历史/循环增强 | 显式周期、WAIT 和动作条件历史 | 让 anti-loop reward 与模型观察对齐 |
| continuous-v5 | 140-D | 箱区方向/密度、放弹目标距离、跨步保留炸箱目标、剩余箱子比例 | 解决局部距离不足和放弹后的长期资源目标丢失 |
| continuous-v6 | 160-D | v5 + 20 维命名对手跟踪、相对运动、动作后距离变化、火力线、逃逸空间 | 改善追击和攻击时机 |
| continuous-v7 | 162-D | v6 + 本局击杀比例、是否已首杀 | 让 r21/r22 的阶段变化对 learner 可观察 |
| continuous-v8 | 163-D | v7 + `survivable_crate_bomb_utility` | 联合表达“能炸箱”与“放弹后能生存” |
| continuous-v9 | 139-D | 从 v8 删除 24 个恒定或精确冗余字段；按 `KEEP_INDICES` 投影 | 降低冗余和输入复杂度，不新增能力 |
| continuous-v10 | 170-D | 从 v7 分叉，增加 Agent 中心四象限箱子/对手密度 | 提供长期区域方向，但不考虑可达性 |
| continuous-v11 | 170-D | 从 v7 分叉，增加四象限可达箱份额与最近可达箱前沿距离 | 用可完成的区域目标替代原始密度 |
| spatial-v6 | 160-D + 12×17×17 | v6 向量与小型 CNN 棋盘分支融合 | 检验空间表示是否优于纯连续向量 |

注意：v10 与 v11 都从 v7 分叉，v11 不是 v10 的后继；v9 是 v8 的压缩投影，不能用简单截断迁移。

### 2.2 Reward 版本（Rainbow 主线相关）

| Reward | 父版本 | 具体尝试 | 要验证的假设 |
|---|---|---|---|
| r7 safe credit | 早期安全主线 | 强自杀/不安全放弹惩罚；用于 continuous-v2 对照 | Rainbow + 旧表示是否已有足够学习能力 |
| r8 constrained | r7 sparse | 去掉预测炸箱 BOMB 正奖励；加入可避免致命动作 -20，自杀压过正事件 | 不鼓励“看起来有用但必死”的动作 |
| r10 bounded history | r9 anti-loop | 用有界真实循环和 WAIT 历史惩罚替代启发式项 | 降低停滞且让奖励条件可观察 |
| r17 global crate bomb discipline | 独立回归主线 | 恢复稳健资源权重；无用炸弹 -1，成功炸弹按实际用途结算部分信用 | 建立 v5 的资源基线 |
| r18 wait attractor escape | r17 | WAIT 历史惩罚由 -0.04×3 加强为 -0.2×5；有效 BOMB 计为进展 | 从长期 WAIT 吸引子中退出 |
| r19 | r18 | 对手距离势能 0.5；安全威胁对手的 BOMB +0.5 | 更积极追击和攻击 |
| r19a | r18 | 对手势能 0.2；安全攻击 BOMB +0.1 | 减弱 r19 的攻击压力 |
| r19b | r18 | 对手势能 0.2；安全攻击 BOMB 即时奖励 0 | 只保留位置压力，避免为预测奖励乱放弹 |
| r20 outcome credit | r18 | 对手势能 0.5，但预测性炸箱/攻击 BOMB 正奖励均为 0；只按真实事件结算 | 减少高频但无实际收益的 BOMB |
| r21 phase potential | r20 | 按箱子阈值 8/28 与首杀状态连续改变金币、箱子、对手、危险势能 | 在资源、追击、保优势间动态切换 |
| r22 two-phase | r20 | 只保留首杀前/后两阶段；首杀后权重为金币 0.9、箱子 0.1、对手 0.15、危险 1.5 | 降低 r21 的非平稳性和参数量 |

### 2.3 Mask 版本

| Mask | 核心准入证明 | 本文 Rainbow 运行中的角色 |
|---|---|---|
| survival-mask-v1 | H=7 内至少存在一条生存路径；无安全动作时回 physical Q | 初始 Rainbow 与部分旧特征实验 |
| survival-mask-v5 | 对新 BOMB 和完整己方炸弹危险期求反馈可控生存集；第一步精确、后续保守；搜索失败 fail-closed | 最终 v5 主线及多数 v6–v11 分支 |

V5 主线使用 `survival-mask-v5/all`：探索、训练贪心、冻结推理和 bootstrap 均受同一准入边界约束。mask 只否决未通过证明的动作，不替 Q 网络选择方向。本文没有找到 Rainbow 内部在冻结权重、相同 worlds 下只改变 mask-v1/v5 的完整大样本消融，因此不能把 V5 组合的全部提升归因于 mask-v5。

## 3. 实验决策时间线：组合、结果与下一步

本节是本文主体。它不按版本号罗列实现，而是恢复当时的实验推理：前一个组合暴露了什么问题，为什么下一次同时或单独改动 feature、reward 或 mask，以及改动后实际观察到了什么。

### 3.1 2026-09-16 凌晨：先从 V4/R10 转向 V5/R17，解决资源目标丢失

**起点问题。** 早期 Rainbow Lite 使用 `continuous-v4 + r10_bounded_history_anti_loop + survival-mask-v1/all`。V4/R10 已让模型观察 WAIT 与循环历史，但 Task 2 的核心问题不只是短期循环：放弹后箱子消失、金币显露，模型经常丢失原来的资源方向。继续加强循环惩罚可能只会把 WAIT 转成往返。

**因此采用的组合。** 2026-09-16 05:22–05:43 CEST 训练：

```text
Rainbow Lite
+ continuous-v5（140-D）
+ r17_global_crate_bomb_discipline
+ 当时配置的 survival mask
+ Task 2, seed 11, 150-round checkpoint
```

V5 新增箱区方向和密度、放弹目标距离、跨步保留的炸箱目标与剩余箱子比例；r17 同时回到较稳健的全局炸箱纪律，无用炸弹 -1，并按炸弹实际用途给予信用。

**冻结结果。** 10 局中平均金币 7.10/9、炸箱 95.9、自杀 0%、长 WAIT 40%、长往返 0%。

**判断。** V5/R17 已经能安全完成大量炸箱，但 40% 长 WAIT 表明全局资源表示本身没有消除停滞。此时下一步不再加新 feature，而是只针对 WAIT attractor 改 reward。

### 3.2 2026-09-16 清晨：R17 → R18，专门攻击 WAIT attractor

**为什么改。** 上一步的主要失败指标是长 WAIT 40%，而不是自杀或不会炸箱。因此保留 V5，只把 r17 改成 r18：WAIT 历史惩罚从 -0.04×3 加强到 -0.2×5，并让有效 BOMB 计为任务进展，避免模型靠放弹重置停滞记账。

**组合与时间。** 2026-09-16 05:58–06:13 CEST：

```text
continuous-v5 + r18_wait_attractor_escape + 同一 Rainbow learner / safety family
Task 2, seed 11, 150-round checkpoint
```

**冻结结果。** 10 局平均金币由 7.10 提高到 7.80，炸箱由 95.9 提高到 115.4，长 WAIT 从 40% 降到 0%，自杀仍为 0%；但长往返从 0% 变为 10%。继续训练到完整 500 局父链后，另一组 10 局诊断达到 8.70/9 金币、117.2 箱、0% 自杀、0% 长 WAIT/往返。

**判断与下一步。** R18 对资源阶段是积极信号，所以 V5/R18 被保留为资源主线。但 Task 3/4 需要追击对手；V5 只有较弱的对手描述，reward 也主要围绕资源。因此下一步不是继续增强 WAIT 惩罚，而是增加显式对手跟踪，并探索攻击 reward。

### 3.3 2026-09-16 傍晚：V5/R18 → V6/R19，加入对手跟踪和主动攻击奖励

**为什么改。** V5/R18 在 Task 2 强，但进入 Task 4 后需要知道“正在追哪个对手、对手往哪走、动作后是否进入火力线、目标是否有逃逸空间”。因此将 feature 从 140-D V5 扩展为 160-D V6，同时从 r18 派生 r19：对手距离势能 0.5，安全形成威胁的 BOMB 即时奖励 +0.5。

**组合与迁移。** 使用旧 `r370` 父 checkpoint 做显式输入扩展：复制 V5 的 140 个输入列，新增 20 列置零；optimizer/replay 按迁移流程重置。2026-09-16 20:18–20:25 CEST 完成 V6/R19 c0100。

**结果。** Task 4 的 10 局诊断为 3.50 分、1.50 金币、0.40 击杀、20% 第一率，但只有 50% 存活且自杀 40%。扩大到 20 局稳定性诊断后变为 3.00 分、0.30 击杀、40% 存活、55% 自杀。继续到 c0200 又下降到 1.20 分、0 击杀、50% 自杀。

**判断。** 显式追击信号可能提高了短期击杀，但“预测有威胁就奖励 BOMB”可能驱动过度放弹；得分高点伴随严重自杀，而且继续训练迅速退化。因此下一步保留 V6 对手特征，先移除预测性 BOMB 正奖励，转向真实 outcome credit。

### 3.4 2026-09-16 晚间：V6/R19 → V6/R20，只按真实结果结算攻击

**为什么改。** R19 在放弹时根据预测用途立即给正奖励，模型可能在尚未真正炸箱或击杀时就获得信用。R20 从 R18 出发，保留对手势能 0.5，但把预测性炸箱和攻击 BOMB 正奖励均设为 0，只在后续实际发生 `CRATE_DESTROYED` 或 `KILLED_OPPONENT` 时结算。

**组合与时间。** 2026-09-16 21:37–21:53 CEST 完成 V6/R20 c0100；之后继续评估 c0156、c0200、c0300、c0400。

**结果序列。** 10 局诊断中：c0100 为 3.40 分、0.40 击杀、20% 自杀；c0156 降到 1.80 分、0.10 击杀、50% 自杀；c0200 恢复到 3.20 分、0.40 击杀、30% 自杀；c0300 为 3.40 分、0.40 击杀但自杀又升至 50%；c0400 下降到 2.00 分。

**判断。** 去掉预测 BOMB 奖励没有稳定解决训练波动，说明问题不只是 reward 中一项即时奖励。此后分成两条探索：一条降低优化漂移并比较 r19/r19a/r19b；另一条让 reward 的资源/战斗阶段变化对模型可观察。

### 3.5 2026-09-16 深夜：V6 Stable + r19/r19a/r19b，检查是不是攻击压力和更新漂移过强

**为什么改。** V6/R19/R20 在相邻 checkpoint 间剧烈波动。为区分“reward 太激进”与“连续训练漂移”，V6 Stable 同时把学习率降为 1e-4、每四次 observation 更新一次、PER 容量设为 100,000，并保护 10,000 条高回报经验；reward 则平行比较：

- r19：对手势能 0.5，安全攻击 BOMB +0.5；
- r19a：降为 0.2 和 +0.1；
- r19b：势能 0.2，攻击 BOMB 即时奖励 0。

**20 局结果。** r19 两次诊断分别为 1.30/1.85 分，自杀均 55%；r19a 为 1.25/1.85 分，自杀均 35%；r19b 为 1.75/3.15 分，自杀 55%/40%。r19b 第二次达到 3.15 分、0.30 击杀和 30% 第一率，但第一次只得到 1.75。

**判断与下一步。** 减弱即时攻击奖励能在部分运行降低自杀，但没有一致提高得分；r19b 的局部高点不能复现。于是问题被重新定义为：固定强度的资源/攻击权重可能不适合整局。下一步在 feature 中加入可观察的首杀状态，再让 reward 按局势切换。

### 3.6 2026-09-16 深夜至 09-17 凌晨：V7/R21，让“阶段奖励”成为可观察状态

**为什么改。** 如果首杀前应追击、首杀后应保住优势，那么 reward 的权重变化必须让 learner 看得见，否则同一个 feature state 会对应不同奖励过程。V7 因此在 V6 后增加本局击杀比例和是否已首杀两维；R21 则按箱子数量阈值 8/28 与首杀状态调整金币、箱子、对手和危险势能。

**先做短 control。** V7/R20 c0050 的 Task 3 10 局结果是 5.70 分、2.70 金币、0.60 击杀、50% 第一、20% 自杀。相同阶段的 V7/R21 control 为 5.00 分、0.50 击杀、50% 第一、20% 自杀，没有显示即时增益。

**仍继续训练的原因。** 阶段 reward 可能需要经历首杀状态后才形成差异，所以继续得到 c0100–c0500：均分依次为 7.40、5.50、7.30、7.40、4.90；击杀为 0.70、0.50、0.60、0.70、0.50；长 WAIT 为 0%、40%、50%、30%、0%。Task 4 旧父链的 c0100–c0400 得分又是 2.0、3.9、1.1、2.7。

**判断。** V7/R21 证明“可观察阶段信号”在工程上成立，c0100/c0400 也出现 7.4 分局部高点，但中间和后期反复退化，Task 4 高点也不持续。因此不把 r21 认定为胜者；下一步分别探索更直接的安全资源交互、紧凑表示和长期区域目标。

### 3.7 2026-09-17 凌晨：V8/R21，直接告诉模型“这颗炸弹既能炸箱又能活”

**为什么改。** V7 分开描述“炸得到箱子”和“存在逃生路径”，网络需要自己学习二者的交互。V8 增加单一事实特征 `survivable_crate_bomb_utility`，只有当前 BOMB 能影响箱子且在 horizon 内可生存时才非零。

**组合与时间。** 从 V7 c0400 迁移，使用 V8/R21/mask family，2026-09-17 02:12–02:29 CEST 训练到 Task 4 c0100。

**结果。** 10 局为 2.50 分、1.00 金币、0.30 击杀、10% 第一、40% 存活、50% 自杀。

**判断与下一步。** 单个“安全炸箱机会”交互特征没有改善实际比赛指标。V8/R22 和 V9/R22 虽完成配置/迁移设计，但未留下统一冻结性能证据。此后不再沿 V8→V9 线性叠加，而是从 V7 分出两个长期方向实验：V10 原始象限密度与 V11 可达箱目标。

### 3.8 2026-09-17 凌晨：V10/R21，尝试用四象限密度提供长期方向

**为什么改。** Task 3/4 的 WAIT 可能来自局部目标耗尽后不知道应该向棋盘哪一侧移动。V10 从 V7 分叉，加入 Agent 中心四象限的箱子和对手密度，共 8 维；它不继承 V8/V9。

**组合与时间。** 从 V7 c0400 迁移，`continuous-v10 + r21 + survival mask`，2026-09-17 03:51–03:54 CEST 训练 50 局。

**结果。** Task 3 的 10 局诊断为 5.70 分、3.20 金币、0.50 击杀、50% 第一、80% 存活、20% 自杀、30% 长 WAIT。

**判断与下一步。** 原始密度会把墙后不可达箱子也计入目标，且结果没有超过 V7/R21 的局部高点。下一步用 BFS 可达箱前沿替代简单密度，并为了减少阶段 reward 的干扰回到更简单的 r20。

### 3.9 2026-09-17：V11/R20，用可达区域目标替代原始密度

**为什么改。** V10 只知道某象限箱子多，不知道能不能走到箱子旁。V11 同样从 V7 分叉，8 个新字段改为四象限可达箱份额和最近可达箱前沿距离；reward 使用 R20，以减少 R21 阶段权重带来的额外非平稳性。

**结果随 checkpoint 的变化。** 10 局均分从 c0050 到 c0500 依次为 3.90、5.50、4.30、4.20、4.60、4.50、4.90、6.20、6.30、3.20。局部最好 c0450 为 6.30 分、3.30 金币、0.60 击杀，但同时只有 50% 存活、50% 自杀；继续到 c0500 后跌到 3.20 分。

**判断。** 可达目标比原始密度更符合任务语义，但结果仍高度非单调，局部高分与严重自杀同时出现，没有形成比 V5 主线更可靠的候选。因此停止继续增加区域 feature。旧材料中的“V11 c500 = 9.9 分”与当前原始 `summary.csv` 不符；对应目标 Agent 行实际是 3.2 分。

### 3.10 2026-09-20：停止多轴漂移，回到固定 V5/R18/mask-v5 重建完整课程链

**为什么回退。** 到 V11 为止，feature、reward、父 checkpoint 和训练预算经常同时变化，短诊断出现过高分，但没有一个新组合在稳定性、自杀、WAIT 和任务保持上统一胜出。为了得到可解释的报告主线，冻结为：

```text
Rainbow Lite
+ continuous-v5（140-D）
+ r18_wait_attractor_escape
+ survival-mask-v5/all
+ seed 11
```

这里选择 V5/R18 不是因为它在所有短实验中分数最高，而是因为它已有最清楚的资源能力、较低自杀和可继续审计的父链；mask-v5 则把放弹责任前移到完整己方炸弹危险期的反馈可控生存证明。

**Task 1 决策。** c0100 已达 50/50，但平均 173.5 步；c0300 仍为 50/50，下降到 136.0 步且无长 WAIT/往返，所以保留 c0300 作为更快的导航快照。c0400 一度退化到 49.95 和 95% 全收集，进一步证明不能取最后 checkpoint。

**Task 2 决策。** c0200/c0300/c0500 都达到 8.60 金币，但分别有 15% 往返、10% 往返或 15% 长 WAIT；c0800 为 8.45 金币、60% 全收集、113.4 箱、0% 自杀且 WAIT/往返均为 0，因此选择 c0800 进入 Task 3。

**Task 4 决策。** c1200 与 c1400 的 20 局均分同为 3.25；c1200 第一/独占第一为 40%/35%，高于 c1400 的 30%/20%，因此先选 c1200。c1500 的存活 95%、WAIT 0% 更干净，但均分只有 2.75，未替代开发候选。

### 3.11 2026-09-21：1,000 局复核推翻“小样本 3.25 分”的乐观判断

**为什么扩大评估。** c1200 是在 20 个开发世界上选出的，65% 长 WAIT 已提示可能过拟合或方差很大，所以使用 50 seeds × 20 rounds 做 1,000 局冻结诊断。

**最终判断。** V5/R18/mask-v5 已解决大部分明显自杀，并完成 Task 1–4 的单 seed 课程链，但没有解决强对手环境中的长期目标停滞。前面的 r19–r22 与 V6–V11 探索也没有提供稳定替代方案，因此不再以短期最高分选择复杂版本。报告中的最终结论应是“复杂 feature/reward 没有被统一协议确认”，而不是“版本越高越差”或“R18 单独导致 WAIT”。

## 6. 从这些尝试能得出的结论

1. **固定 V5/r18/mask-v5 确实完成了单 seed 的 Task 1–4 课程链。** Task 1 在 c0100 已满分，Task 2 c0800 提供 8.45/9 金币且无长 WAIT/往返，Task 3 c0300 提供 7.80 分、0.65 击杀和 0% 长 WAIT。
2. **checkpoint 性能明显非单调。** Task 3 c0200→c0600 和 Task 4 c1200→c1300 都出现显著退化；“训练更久”不是选最后 checkpoint 的理由。
3. **r18 在最接近的局部对照中优于 r17。** 10 局诊断中金币 7.1→7.8、炸箱 95.9→115.4、长 WAIT 40%→0%，但出现 10% 长往返，且仍缺大样本、多 seed 纯 reward 复现。
4. **强攻击 reward 没有稳定提高 Task 4。** r19、r19a、r19b 结果方差大，高得分运行常伴随 35%–55% 自杀；r20 去预测性 BOMB 奖励后个别 checkpoint 更稳，但没有稳定胜出。
5. **阶段 reward 可实现，但未被确认。** V7 让首杀状态可观察；r21 在 c0100/c0400 出现 7.4 分，但中间和后期退化，且 Task 4 不稳定。
6. **更多 feature 没有形成可靠增益。** V8 的安全炸箱交互、V10 的象限密度和 V11 的可达箱目标均有局部信号，但没有统一大样本胜者。V9 只证明可压缩，Spatial V6 只完成工程 smoke。
7. **最终主要瓶颈不是自杀，而是长期停滞。** V5 c1200 的 1,000 局评估中自杀仅 0.7%，但长 WAIT 达 57.1%，平均得分只有 2.938。

最稳妥的论文表述是：

> 在 V5 资源主线之后，我们分别探索了对手跟踪、攻击信用、首杀阶段、安全炸箱交互、紧凑表示和区域目标。部分小样本 checkpoint 出现更高击杀或得分，但结果对 checkpoint 和诊断 worlds 高度敏感，并常伴随自杀、WAIT 或后期退化。由于这些分支没有保持相同父权重、训练预算和评估协议，现有证据不能支持 V6–V11 或 r19–r22 的公平排名。团队因此停止继续叠加复杂 feature/reward，回到证据最完整的 V5/r18/mask-v5 合同完成课程链，并用 1,000 局扩展评估识别其长期 WAIT 瓶颈。

## 8. 尚缺的严格实验

若要把本文中的探索性结论升级为可发表的因果消融，至少需要：

1. 固定同一个父 checkpoint、训练 seed、环境 worlds、训练预算、探索日程和 mask，只比较 r18/r20/r21/r22；
2. 固定 reward 与 mask，只比较 v5/v6/v7/v8/v9/v10/v11，并使用兼容的显式迁移；
3. 固定权重、feature、reward 和 worlds，只切换 mask-v1/v5，报告自杀、veto、fallback、guarantee loss、放弹率、任务保留与完整 act 延迟；
4. 每个候选至少用多训练 seed 复现，再用未参与选择的冻结 worlds 做一次独立确认；
5. 同时报告得分、金币、击杀、第一率、生存、自杀、被杀、长 WAIT、长往返和 CPU 延迟，避免单指标选模。

在这些实验完成前，本文的 V6–V11 与 r19–r22 数字应作为失败分析和后续假设来源，而不是版本排行榜。
