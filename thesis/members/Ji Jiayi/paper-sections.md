## §4.1 输入
**Q-learning。** Task 1 需要在有限步数内找齐可见金币；Task 2 又增加了箱子、炸弹和隐藏目标。Q-learning 路线把局面压缩为 84 个数值，记录目标可达性、邻近危险、放弹条件和近期动作。每个候选动作只读取与自身有关的 29 个数值，再通过 tile coding 映射到参数表。Tile coding 可以理解为几组边界略有错开的网格：相近局面通常激活部分相同格子，因此一次更新也会影响相似局面的估值。输入提供环境事实，不直接告诉学习器该向哪个方向走。

**CNN。** Q-learning 的数值输入需要事先挑选与动作有关的信息；CNN 路线让网络读取带位置的棋盘。模型把局面表示为 17 个二维通道：前 12 个记录墙、箱子、金币、玩家、炸弹、爆炸和危险，其余通道记录到目标的距离、上一位置与近期访问情况。到金币、箱子前沿和对手的广度优先搜索距离只是空间线索；网络仍需学习如何利用这些线索选择动作。最终实验使用修正过玩家位置通道的输入版本；早期错误及其影响见[附录 B](#附录-bcnn-变体与失败实验)。

## §4.2 奖励

两条路线都用游戏事件奖励收集金币、炸箱和生存，并借助团队共享的奖励与安全组件。Q-learning 的导航训练还使用基于距离的势能变化：$F(s,s')=0.95\Phi(s')-\Phi(s)$。它让模型在真正捡到金币之前，也能收到接近目标的训练反馈 [@ng1999policy]。Task 2 的目标型 WAIT 变体只在当前位置安全、存在可达目标且有安全推进动作时，对原地等待追加 $-0.04$；躲避爆炸所需的等待不受这项惩罚。这个额外惩罚不是上述势能差的一部分，因此不能据势能塑形理论声称整套奖励保持最优策略不变。

CNN 的 Task 2 基线使用较稀疏的金币、炸箱和生存反馈。它的条件 WAIT 变体同样只处罚安全且存在推进机会的原地等待。Task 2 中，两条学习器先从物理上可执行的动作出发，再由团队的生存掩码排除有限预测窗口内找不到存活路线的动作；Q 值只在剩余动作中决定选择。掩码约束动作准入，不替代模型规划目标，也不保证预测窗口之外的安全。我们在冻结 CNN 上单独检查了关闭掩码的后果，避免把安全效果误当成网络学到的能力。

## §4.3 模型

**Q-learning 模型。** 主模型使用两组动作价值权重。当前动作激活的 tile 参数之和给出该动作的 Q 值；更新时一组权重选择下一动作，另一组权重估计其价值，然后交换角色。这样的 Double Q 更新旨在减轻最大值操作带来的高估，但本项目没有单独测量高估幅度 [@hasselt2010doubleq]。Watkins Q($\lambda$) 的资格迹把后续奖励分给近期状态与动作；执行非贪心探索动作后，学习器清除旧迹，避免继续更新探索前的动作 [@watkins1992qlearning]。

**CNN 模型。** 模型用不降采样的残差卷积处理 17 通道棋盘，再以全局输出头预测六个动作的 Q 值。不同膨胀率的卷积层读取近处和较远处的棋盘关系。训练采用 Double DQN：在线网络在下一状态选择动作，目标网络估计该动作的价值；经验回放让网络重复使用已观察到的状态转移 [@mnih2015human; @vanhasselt2016double]。全局输出头与其他结构的筛选记录见[附录 B](#附录-bcnn-变体与失败实验)。

CNN 的 Task 1 训练还使用团队已经训练并冻结的模型作为教师。教师给出合法动作的价值分布，学生通过 Kullback-Leibler（KL）散度学习这些动作的相对偏好 [@rusu2015policy]。教师只提供训练信号；冻结推理只加载学生 CNN 权重。Task 2 继续使用原 Task 1 教师数据作为导航约束，并没有采集新的 Task 2 教师轨迹。教师模型、共享特征、奖励和安全掩码属于团队协作成果，不能归为 CNN 路线的个人独立发明。

## §5 训练

两条路线先在没有箱子和对手的 Task 1 学习收集 50 枚可见金币，再进入有箱子、无对手的 Task 2。训练 seed 决定一条学习链；评估 seed 只决定冻结模型遇到的环境。我们按固定开发集选快照，再在未用于选模的环境上检查固定 checkpoint。训练 reward 不作为晋级指标，正式动作延迟在单线程 CPU 上测量。

Q-learning 先以训练 seed 11 比较单表基线和 Double Q($\lambda$)。主模型训练约 10 万个环境动作，折扣率 $\gamma=0.95$、资格迹参数 $\lambda=0.8$，学习率从 0.08 降到 0.02；训练使用学校集群的单线程 CPU。最早通过 Task 1 独立确认的 checkpoint 使用 safety off。为使 Task 2 的父模型与后续安全设置一致，我们另从零训练 safety-all 的 Task 1 父链，经过连续三次冻结能力检查和独立晋级审计，才开放 BOMB 继续训练 Task 2。附录 A 分开记录后续变体的父链与奖励合同。

CNN 的 Task 1 先采集冻结教师在独立环境种子中的轨迹，再用合法动作上的 KL 损失训练学生。全局头通过开发评估和另一组 100 局保留评估后，成为 Task 2 的初始权重。Task 2 使用四步回报、经验回放和 $5\times10^{-5}$ 的学习率，并保留教师 KL 项约束导航行为；它没有重新蒸馏 Task 2 教师。蒸馏和 Task 2 训练使用学校集群的一张 GTX 1080 Ti，冻结评估仍在单线程 CPU 上完成。我们保存不同训练步数的 checkpoint，并按冻结任务指标选择模型。

## §6.2 Task 1
Task 1 的主要指标是 50 枚金币的全收集率和平均金币数。Q-learning 开发集为 seeds 10000 至 10004、每 seed 20 局；CNN 开发集为 seeds 10001 至 10005、每 seed 20 局。固定模型后，Q-learning 在 seeds 11000 至 11099 各评估一局，CNN 在另一组 seeds 21000 至 21099 各评估一局。下表分开列出开发选模与独立检查；两条路线的确认环境不同，不能据数值给学习器排序。

| 路线与模型 | 评估用途 | 局数 | 全收集率 | 平均金币 |
|---|---|---:|---:|---:|
| Q-learning 单表基线 | 开发集最佳快照 | 100 | 71% | 47.98/50 |
| Q-learning Double Q($\lambda$) | 开发集选中快照 | 100 | 96% | 49.51/50 |
| Q-learning Double Q($\lambda$) | 独立确认 | 100 | **96%** | **49.58/50** |
| CNN 全局输出头 | 保留环境 | 100 | **96%** | **49.84/50** |

单表基线与 Double Q($\lambda$) 的比较同时改变了状态表示和学习器，不能把差距单独归因于 Double Q。固定 Double Q($\lambda$) 的 100,008 步 checkpoint 后，独立确认仍有 96 局捡满；完整 CPU 决策最大耗时为 11.63 ms。修正输入后的路径 CNN 最佳开发结果为 17% 全收集；加入团队教师训练后，选定的全局头在 100 局开发评估中达到 97%。这些模型同时改变了训练方式，差异不能单独归因于蒸馏。固定全局头的保留评估为表中 96%，完整 CPU 决策 P95／最大值为 8.39／15.55 ms。各版本及在线微调的结果见[附录 B](#附录-bcnn-变体与失败实验)。

**结论。** 两条价值学习路线分别在未参与选模的 Task 1 环境中超过了预设的 90% 全收集门槛。确认结果证明各自具备可见金币导航能力；它们没有共同的确认 seed 集合，不能构成严格的同环境算法对照。

## §6.3 Task 2

Task 2 包含 9 枚隐藏金币。我们同时检查平均金币、炸箱、自杀、长时间 WAIT、长往返和 Task 1 能力保持，因为炸箱数量或训练奖励单独上升不能证明任务完成。下表只展示两条路线各自的代表 checkpoint：Q-learning 训练 seed 11 在开发 seeds 10000 至 10019 各评估一局；CNN 训练 seed 22 的候选固定后，在主验证 seeds 11000 至 11099 各评估一局。

| 路线 | 评估用途／局数 | 平均金币/9 | 全收集率 | 平均炸箱 | 长 WAIT／长往返问题局率 | 自杀率 |
|---|---|---:|---:|---:|---:|---:|
| Q-learning 目标型 WAIT 版本 | 开发集／20 | 3.95 | 0% | 53.45 | 30%／75% | 0% |
| CNN 条件 WAIT 版本 | 主验证／100 | 2.60 | 0% | 44.15 | 43%／79% | 0% |

Q-learning 的代表模型在 200k Task 2 动作后保留了 Task 1 能力：同一 checkpoint 回测平均收集 50/50 枚可见金币，已结算炸弹存活率为 100%。但其 20 局 Task 2 开发评估全部跑满 400 步，平均金币和炸箱仍低于预设的 6/9 与 60 门槛；CPU 决策 P95／最大值为 11.32／81.80 ms。较高的长往返问题局率说明安全放弹后仍存在目标推进不足，但当前证据不能把这一现象单独归因于特征或奖励。

CNN 的同 seed 开发对照给出更明确的局部变化：加入条件 WAIT 反馈后，200k 快照的平均金币由 2.00 升到 2.80，平均炸箱由 34.35 升到 54.20，WAIT 动作占比由 55.20% 降到 17.26%。我们再独立训练另外两个 seed，并按开发集选定其中一个 checkpoint。选中模型的 20 局开发结果为 4.20 金币和 67.25 炸箱；固定后的一次 100 局主验证则为表中 2.60 金币和 44.15 炸箱。主验证的已结算炸弹存活率为 100%，完整 CPU 决策 P95／最大值为 8.88／19.11 ms。条件 WAIT 改善了开发阶段的等待行为，但主验证仍有 43% 的对局出现长 WAIT；其他奖励与安全对照见[附录 B](#附录-bcnn-变体与失败实验)。

**结论。** 两条路线在启用生存掩码时都表现出放弹和部分炸箱能力，代表评估中没有观察到自杀。配对检查表明掩码对 CNN 的安全表现有直接作用，不能把安全性全部归因于网络学习。现有结果也不支持“完成 Task 2 隐藏金币收集”的结论。两行代表结果的评估用途和样本量不同，不能据均值判断 Q-learning 或 CNN 谁更强。

## §6.6 变体及失败原因
两条路线均曾在 Task 1 学会导航，却没有在 Task 2 的代表评估中完成隐藏金币目标。Q-learning 的一些变体减少了长 WAIT 或往返，但没有同步增加金币；CNN 的条件 WAIT 反馈改善了开发评估，固定模型在主验证中仍有循环。CNN 的同 checkpoint 配对评估还显示，关闭生存掩码会降低炸箱并增加自杀。各变体的父链、预算和评估集并不一致，故不能将其排为单因素消融榜。具体改动、失败结果与未运行分支分别列于[附录 A](#附录-aq-learning-变体与失败实验)和[附录 B](#附录-bcnn-变体与失败实验)。

**结论。** 减少一种循环指标或提高安全炸箱能力，都不足以证明模型已经学会持续追踪隐藏金币。现有历史输入与奖励实验使用了不同父链或预算，五步回报对照没有运行；若要判断这些因素对金币完成率各自的作用，还需要统一条件下的消融。

条件 WAIT 的开发结果不能替代 seed 22 候选的 100 局主验证。该主验证只有 2.60/9 平均金币、0% 捡满，表明安全放弹和减少部分等待仍不足以完成隐藏金币收集。这里的“通过”仅指预注册的安全炸箱迁移门槛，不是 Task 2 全金币目标。
