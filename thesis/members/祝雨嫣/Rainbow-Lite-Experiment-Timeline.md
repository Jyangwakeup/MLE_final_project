# Rainbow Lite 

## Experiment

### 1. 建立 Rainbow Lit基线

最初的 `rainbow_lite_agent` 在 Double DQN 上加入三个组件：

- Dueling network
- Proportional Prioritized Experience Replay
- 固定 4-step return

它只是 Rainbow 的精简组合，没有完整 Rainbow 的 distributional RL、noisy network 等组件，所以称为 Rainbow Lite。

建立初始方向：

- `rainbow_lite_continuous_v2_agent`+survival mask v1：在旧的 84 维 `continuous-v2` 上运行 Rainbow，用于区分算法变化和表示变化。

## 2. 在survival mask v1版本上探索feature+reward方案

| 版本       | 来源        | 核心变化                                 | 研究目的                             |
| ---------- | ----------- | ---------------------------------------- | ------------------------------------ |
| V6         | V5          | 对手跟踪、相对运动、火力线、对手逃逸空间 | 改善追击和攻击判断                   |
| V6 Stable  | V6 平行分支 | 调整对手压力与稳定性设置                 | 检查 V6 的不稳定是否来自过强攻击激励 |
| V7         | V6          | 加入本局击杀数和是否已首杀               | 让阶段奖励使用可观察状态             |
| V8         | V7          | 加入“可生存的炸箱机会”                   | 联合表达炸箱收益与逃生可行性         |
| V9         | V8          | 从 163 维压缩到 139 维                   | 删除常量和冗余字段，降低输入复杂度   |
| V10        | 从 V7 分叉  | Agent 中心四象限箱子/对手密度            | 提供更长期的区域方向                 |
| V11        | 从 V7 分叉  | 四象限可达箱目标和距离                   | 用可达目标替代简单密度               |
| Spatial V6 | 独立分支    | 空间棋盘表示                             | 检验卷积表示是否优于连续向量         |

这些分支通常同时使用 r19–r22：

- r19/a/b：不同强度的对手压力。
- r20：取消预测性 BOMB 正奖励，只按实际炸箱和击杀结算。
- r21：根据箱子密度和是否首杀连续调整势能。
- r22：简化为首杀前、首杀后两个阶段。

结果：

- 课程要求报告失败、无改善和放弃的方案。

- V6–V11 能解释为什么团队最终回退到固定 V5，而不是机械选择最高版本。

- 这些实验的协议、预算和样本量不统一，部分运行中断，所以不适合写成正式版本排行榜。

| 分支      | 主要假设                   | 实际状态                           | 能得出的结论                   |
| --------- | -------------------------- | ---------------------------------- | ------------------------------ |
| V6        | 显式对手跟踪能改善追击     | 完成局部实验，协议与 V5 不完全一致 | 未形成可确认的稳定增益         |
| V6 Stable | 减弱对手压力可改善稳定性   | 平行消融                           | 未得到统一协议下的胜出证据     |
| V7        | 首杀状态可支持阶段奖励     | 有训练及中断记录                   | 阶段信号可实现，但效果未确认   |
| V8        | 安全炸箱机会能改善资源决策 | 已实现、局部测试                   | 没有充分性能验证               |
| V9        | 删除冗余特征可降低复杂度   | 已实现迁移和测试                   | 证明表示可压缩，不等于性能提升 |
| V10       | 象限密度能提供长期方向     | 局部实验                           | 未证明优于 V5/V7               |
| V11       | 可达箱目标比原始密度更有效 | 小样本曾出现高分                   | 10 局结果不足以支持胜出        |

总结：

> 在完成 V5 资源主线后，我们依次探索了对手跟踪、首杀阶段、安全炸箱机会、紧凑表示和区域目标等扩展。由于这些分支的父 checkpoint、奖励版本、训练预算和评估样本并未全部保持一致，现有结果只能用于诊断，不能构成 V6–V11 的公平排名。部分分支出现短期高分，但没有在统一的大样本冻结评估中确认稳定增益。因此，我们停止继续增加特征，回到固定的 V5/r18/mask-v5 合同完成 Task 1–4 课程链。

得到的结论 太复杂的feature、reward对性能没有明显增益。

## 3. 最终形成基线

```
Rainbow Lite

+ continuous-v5（140维）
+ r18_wait_attractor_escape
+ survival-mask-v5

```

Feature v5 在此前连续特征上增加：

- 箱子区域方向和密度；
- 放弹目标距离；
- 跨步保留的炸箱目标；
- 剩余箱子比例。

Reward r18 从 r17 发展而来，主要加强长期 WAIT 惩罚，并把有效 BOMB 计为任务进展。Mask v5 则要求在己方炸弹完整危险期内存在反馈可控的生存策略。

这里三个轴同时改变，因此 V5 的结果只能归因于完整组合，不能单独说是 Feature v5、r18 或 mask-v5 带来的提升。
