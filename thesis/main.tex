\authorsubsection{Rainbow Lite：特征、奖励与延迟信用}{祝雨嫣}

在 Bomberman 中，动作的结果经常延迟出现。放置炸弹后还要等待数步，箱子被炸毁、金币出现或
对手被击杀才会形成可观察结果；同一次移动也可能是在接近金币或躲避爆炸。普通 Double DQN
能够降低价值高估，却不能自动解决延迟信用和样本利用效率问题。因此，本路线先检验几项轻量学习
机制，再根据实际失败决定是否增加状态信息或辅助奖励。

Rainbow Lite 由此形成。Dueling network 分开估计局面价值与动作优势；比例优先经验回放
（proportional PER）让时间差分误差较大的样本更常被学习；固定四步回报把随后数步内出现的
箱子、金币或死亡结果更早传回当前动作。这些组件不直接规定 Agent 应该往哪里移动。
本实现没有加入完整 Rainbow 中的 distributional reinforcement learning、noisy network 等组件，
因此只称为 Rainbow Lite。

算法组件确定以后，实验重点转向一个更具体的问题：如果策略仍然停住、循环或错误放弹，原因究竟
是状态中缺少必要信息，还是辅助奖励把学习器推向了不理想的行为？为回答这个问题，团队将设计拆成
三个版本轴。Feature 决定模型能够看到什么，reward 决定训练期间如何分配信用，survival mask
只负责否决在有限时域内无法证明可生存的动作。三个轴的功能不同，但实际开发中曾被同时修改。
所以下文先描述行为问题，再报告结果和停止决定；只有实验条件足够接近时，才解释单个组件的信号。

\authorsubsubsection{导航停滞来自历史缺失还是奖励诱导？}{祝雨嫣}

最早需要处理的并不是得分低，而是策略会在尚有任务可做时停止推进。长 WAIT 指 Agent 连续多步
等待，长往返则指在少数位置之间反复移动而不接近新目标。二者都会消耗 400 步的回合预算，但
成因不同：WAIT 可能来自网络认为移动价值更低，往返则可能表示走出一步后又失去目标。Task 2
中炸弹会改变箱子与金币布局，策略尤其需要重新选择长期目标。

V4/R10 首先尝试让短期停滞变得可观察。V4 提供 WAIT 与动作循环历史，r10 根据真实历史施加
有界惩罚，这使模型至少能够区分“第一次等待”和“已经重复多次的等待”。实际运行却表明，知道
自己正在循环仍不足以决定下一步去哪里。Agent 有时能够完成一次安全炸箱，但箱子消失后便失去
原来的资源方向；如果此时只继续提高循环惩罚，模型可能被迫离开当前位置，却不一定朝有价值的
区域移动。这个观察将问题从“缺少动作历史”推进为“缺少跨越地图变化的目标持续性”。

因此，下一步没有继续扩大历史窗口，而是构造 140 维的 V5 表示。它增加箱子在不同区域的方向
与密度、适合放弹的目标距离、跨步保留的炸箱目标以及剩余箱子比例。直观地说，V5 不只告诉模型
眼前最近的格子，还尽量保留“这颗炸弹原本是为哪个资源目标服务”的线索。与其配合的 r17 恢复
较稳健的全局炸箱纪律：无用炸弹受到惩罚，实际产生用途的炸弹才获得相应信用。该组合在 Task 2
的 10 局冻结诊断中平均收集 7.10/9 枚金币、炸毁 95.9 个箱子且自杀率为 0\%。这说明 Agent
已经能够安全地执行大量炸箱行为，但 40\% 的游戏仍出现长 WAIT，资源信息本身没有消除停滞。

这一结果给出了一个较清楚的下一步：暂时保留 V5，只修改直接针对 WAIT 的奖励。r18 将 WAIT
历史惩罚从较弱的三步累计提高为更强的五步累计，同时把确实推动任务进展的 BOMB 计入进展，
避免 Agent 通过频繁放弹重置停滞判断。相同规模的 10 局局部诊断中，平均金币由 7.10 增至
7.80，炸箱由 95.9 增至 115.4，长 WAIT 由 40\% 降至 0\%，自杀仍为 0\%。然而，长往返
由 0\% 上升至 10\%。因此，这次修改的合理解读不是“停滞已经解决”，而是 WAIT 行为明显减少，
同时少量失败转移成了移动循环。两次运行是否拥有完全相同的父权重和训练预算仍需进一步核对，
所以该结果只作为采用 r18 的局部证据，不作为大样本纯 reward 消融。

此后，团队停止同时更换多个版本，将课程固定为 V5、r18 和 survival-mask-v5/all，并使用
训练 seed 11。训练 seed 控制网络初始化、采样与探索；本路线只有一条完整训练链。checkpoint
只是这条训练链在不同时刻的快照，并非相互独立的模型复现。

固定主线首先重新检查最基础的导航能力。Task 1 的 c0100 已能在 20 个冻结开发世界中收齐
50 枚金币，但平均需要 173.5 步。继续到 c0300 后，平均得分仍为 50.00/50，全收集率仍为
100\%，平均步数降至 136.0，且没有长 WAIT 或长往返。因此，c0300 被保留为更高效的 Task 1
快照。值得注意的是，之后的 c0400 短暂下降到 49.95 枚金币和 95\% 全收集率，这已经说明
checkpoint 表现不会随着训练轮数自动单调提高。

进入 Task 2 后，选择标准不能只看平均金币。c0200、c0300 和 c0500 都达到 8.60/9 枚金币，
但分别伴随长往返或长 WAIT。c0800 的平均金币略低，为 8.45/9，全收集率为 60\%，平均炸箱
113.4 个；它同时保持 0\% 自杀、0\% 长 WAIT 和 0\% 长往返。团队因此牺牲少量开发集均分，
选择行为更干净的 c0800 作为 Task 3 父模型。这是一次多指标的开发选模，而不是独立确认。

V5、r18 与 mask-v5 必须作为同一个实验合同理解：它们分别改变目标信息、训练信用和动作准入，
却在主线中共同变化。即使最终得分提高，也无法判断哪一项贡献最大。因此，本文只说固定组合形成
了可继续训练的资源主线，不把结果拆成三个独立因果结论。

\authorsubsubsection{对手与阶段信息是否改善 Task 3？}{祝雨嫣}

Task 3 加入 peaceful agent 后，任务不再只是寻找资源。即使对手不会主动攻击，它也会占据格子、
收集金币并改变可用路线；到了 Task 4，三个 rule-based opponents 还会主动放弹。此时，Agent
既要知道资源在哪里，也要判断正在接近哪个对手、一次放弹是否真正形成威胁、攻击后是否仍有退路。
V5 对这些信息描述较弱，因此团队首先提出“对手状态不足”的假设，随后又检验“同一套奖励不适合
整局不同阶段”的假设。

V6 在 V5 上增加 20 维对手信息，包括命名目标、相对运动、动作后的距离变化、火力线和对手逃逸
空间。r19 同时提高攻击压力：接近对手获得势能变化，预测能形成安全威胁的 BOMB 立即得到正
奖励。这个设计希望让 Agent 更主动，但结果首先暴露了信用过早的问题。Task 4 的十局诊断中，
V6/r19 c0100 一度得到 3.50 分和 0.40 次击杀，看起来比资源主线更具攻击性；同一 checkpoint
扩大到 20 局后，得分降到 3.00，自杀率由 40\% 升至 55\%。继续训练到 c0200 后，均分又降到
1.20，且没有击杀。短期高分与严重自杀同时出现，不能证明对手特征带来了稳定改善。

r20 随后取消预测性 BOMB 正奖励，只在真实炸箱或击杀后结算信用，但相邻 checkpoint 仍大幅
波动。V6 Stable 又降低学习率、更新频率和攻击权重，并扩大 PER 容量。r19b 的两次诊断分别为
1.75 和 3.15 分，较高结果未能复现，各配置仍出现 35\%--55\% 自杀。由于优化设置与奖励同时
变化，这不是单变量消融，但说明单纯减弱攻击压力没有形成可靠胜者。

第二条思路关注奖励阶段是否可观察。资源丰富时，炸箱和收集金币较重要；获得首次击杀后，继续
冒险追击可能不如保住已有优势。如果 reward 会根据局势改变，而状态却没有说明当前处于哪个阶段，
相似输入就可能对应不同训练信号。V7 因而增加本局击杀比例和是否已经首杀，r21 再根据箱子数量
和首杀状态改变资源、对手与危险势能。工程上，这使阶段变化对网络可见；性能上却仍不稳定。
Task 3 的十局诊断中，c0100 和 c0400 都达到 7.40 分，c0200 降到 5.50，c0500 又降到
4.90。长 WAIT 也在相邻 checkpoint 间从 0\% 波动到 50\%。因此，局部高点不足以确认阶段
奖励的收益。

团队最后尝试给策略更长距离的方向。V10 使用 Agent 周围四个象限的箱子与对手密度，但这种统计
会把墙后不可达的箱子也当作目标。V11 改为可达箱份额和最近可达箱前沿距离，希望告诉 Agent
“哪一片区域实际可以推进”。这个表示更符合任务语义，却没有带来稳定曲线：十局诊断的局部最高
c0450 为 6.30 分，同时自杀率达到 50\%；继续到 c0500 后均分降为 3.20。旧笔记曾把 c0500
写成 9.9 分，但当前原始汇总中目标 Agent 对应行是 3.20，本文采用后者。V8、V9、r22 和
Spatial V6 等分支只有局部测试、工程验证或未完成评估，也没有被包装成性能失败或成功。

在复杂分支没有形成稳定胜者的情况下，Task 3 的晋级仍回到证据较完整的固定主线。由 Task 2
c0800 继续训练后，c0200 的 20 局开发均分为 7.90，第一名率 75\%，但 35\% 的游戏出现长
WAIT。c0300 的均分略低，为 7.80；其平均击杀提高到 0.65，第一名率为 65\%，存活率为
100\%，长 WAIT 降到 0\%。如果只按均分选择，c0200 会胜出；如果同时要求策略能够持续行动，
c0300 更适合作为下一阶段父模型。团队因此接受 0.10 分的开发均分损失，选择 c0300。

继续训练后，c0600 和 c0800
的长 WAIT 分别达到 80\% 和 85\%，c0900 虽恢复到 7.70 分，仍有 70\% 长 WAIT。由此可见，
checkpoint 是同一训练轨迹上的不同快照，较晚快照不必然更成熟。V6--V11 与 r19--r22 的父模型、
训练预算和评估世界又没有全部固定，因此不能把所有短实验排列成公平排行榜。本阶段能支持的结论
只是：对手跟踪、阶段状态和可达目标都能够实现，也产生过局部积极信号，但现有证据没有确认它们
稳定优于 V5/r18/mask-v5 主线。

\authorsubsubsection{Task 4 的残余失败是什么？}{祝雨嫣}

Task 4 同时面对三个 rule-based opponents。与 Task 3 相比，棋盘更拥挤，炸弹来源更多，安全
路线也会随其他 Agent 的动作快速变化。这里存在一个直接的权衡：更主动地抢金币或攻击可能提高
得分，却增加被困和死亡风险；更保守地等待可以提高存活，却可能在 400 步结束前没有完成任何
有效竞争。因此，Task 4 的 checkpoint 不能只按得分或存活率中的一个指标选择。

以 Task 3 c0300 为父模型继续训练时，checkpoint 不断在这些目标间摆动：c0600 的存活率为
80\%，长 WAIT 却升至 65\%；c0900 的存活率达到 90\%，均分只有 2.65。survival mask
能够否决部分致命动作，却不会替学习器选择有收益的方向；通过生存证明不等于会带来更高得分。

开发筛选最终把注意力放在 c1200、c1400 和 c1500。前两个 checkpoint 在各 20 个开发世界中
均得到 3.25 分。c1200 的第一名率和独占第一名率分别为 40\% 和 35\%，高于 c1400 的 30\%
和 20\%，所以 c1200 被暂选为开发候选。然而，它已有 65\% 长 WAIT，显示高分与明显停滞可以
同时存在。c1500 则呈现相反取舍：存活率达到 95\%，长 WAIT 为 0\%，行为看起来更干净，但
均分降至 2.75。团队没有用“最晚 checkpoint”替代开发候选，也没有把更高存活自动解释为更强
策略，而是决定扩大 c1200 的冻结评估规模。

扩展评估保持 c1200 权重不变，在 50 个环境 seed 上各运行 20 局，共得到 1,000 局。环境 seed
控制游戏世界的随机性，不会重新初始化网络或产生新的训练链。该设计能更稳定地估计冻结策略，
却不能回答换一个训练 seed 是否还能学到同样结果。因此，50 个环境 seed 不是 50 次独立训练，
1,000 局也不是 1,000 个独立模型。

样本扩大后，开发集上的乐观估计被明显修正。平均正式得分由 3.25 降到 2.938，平均金币为
2.098，平均击杀为 0.168；第一名率从 40.0\% 降到 26.7\%，独占第一名率从 35.0\% 降到
20.1\%。另一方面，存活率仍有 83.8\%，自杀率仅为 0.7\%，被对手击杀率为 15.5\%。最突出
的诊断指标是长 WAIT：它在 57.1\% 的游戏中出现，而长往返只有 1.0\%。扩展评估不是预注册的
Task 4 正式质量门，但它足以说明 20 局开发高点没有代表整体表现。

从行为角度看，Rainbow Lite 的失败模式发生了转移。早期攻击分支会因过度放弹直接自杀；固定
V5/r18/mask-v5 主线把大样本自杀率降到了较低水平，却经常在仍可安全行动时选择长期等待。换言之，
安全准入解决的是“哪些动作不应执行”，没有回答“剩余安全动作中哪一个最值得执行”。更复杂的
对手、阶段和区域特征也没有在现有协议中稳定修复这一点。后续工作若要改善 Task 4，应优先验证
目标持续性、过度保守和长期信用，而不是仅继续增加即时危险规则或短期攻击奖励。

综合来看，固定主线在单一训练 seed 下形成了 Task 1--4 的完整本地课程链，并提供了可追溯的
checkpoint 决策过程；它并未完成多训练 seed 复现，也不能证明某个 feature、reward 或 mask
单独带来了全部变化。Rainbow c1200 的 1,000 局扩展诊断与 B33 的历史 benchmark 也不属于
同一协议，双方缺少相同世界、对手和冻结条件下的配对比较。因此，本研究不据此声称 B33 在公平
实验中优于 Rainbow Lite。最终提交选择仍需结合各路线的历史证据完整度、CPU 推理开销和打包
可复现性，而 Rainbow 路线最明确的研究贡献，是揭示了低自杀并不等于有效竞争，以及短开发集
高点必须通过更大规模冻结评估重新检验。
