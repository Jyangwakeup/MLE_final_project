# 从金币导航基线到条件循环奖励：Task 1 实验记录与研究思路

记录日期：2026-09-14。范围：两个归档目录中的全部 12 组评估，以及它们引用的训练目录。本文根据本地 metadata、training.csv、episodes.jsonl 和 summary.csv 整理；未启动新训练或评估。它是团队实验工作记录，正式报告使用前应由成员核验并补充主要作者。

## 1. 研究主线：先找到能学会导航的方案，再解决稳定完成问题

这两批实验主要回答一个问题：Agent 能否在没有炸弹、箱子和对手干扰时稳定收集金币，以及为什么一些模型会在收集途中停住或往返移动。

合并两批记录后，当前最好的 Task 1 checkpoint 是 **continuous-v1 + Double DQN + R2**：平均收集 49.52/50 个金币，86% 的局收集全部金币，平均每局 167.43 步。表格模型中 **Double Q + compact 特征 + 含 idle 的 R4** 最好：47.77 个金币、75% 全收集率。这里的“最好”只指这些已评估 checkpoint 在本组 Task 1 场景中的表现，不能据此确定最终对战模型。

将全部实验放在一起，可以归纳出一条研究主线：**建立金币导航任务 → 探索状态表示和价值学习方法 → 用实际游戏指标识别等待与往返问题 → 尝试奖励塑形 → 选择连续特征 Double DQN 作为后续载体 → 用历史可观测的 v2 特征和条件式 R5 奖励做受控验证。**

这里按研究问题的逻辑组织实验。两个目录是归档位置，部分实验并行开展，部分是同一 checkpoint 的重评；以下阶段不声称是严格按时间发生的先后因果链。设计动机是依据实现和结果作出的归纳。

### 1.1 为什么从单人金币导航开始

完整 Bomberman 同时包含寻路、炸箱、逃生和对抗。如果模型表现不好，很难直接判断是导航失败、风险判断错误，还是对手干扰。因此先固定 Task 1：50 个金币、没有箱子和对手、禁止放弹，让模型只解决“选择移动方向并完成收集”这个子问题。

这一步既检验训练流程是否能产生有效策略，也建立后续课程学习的基础。评价时同时看平均金币、全收集率和局步数：平均金币反映总体收益，全收集率反映能否完成任务，局步数反映是否在少量剩余金币上耗尽时间。单看平均奖励或平均金币，都可能忽略停滞问题。

### 1.2 第一条探索线：什么样的模型和状态表示值得继续投入

我们以 Q-learning 和离散特征 DQN 为基础，同时探索紧凑 Double Q、连续特征 Double DQN，以及融合棋盘和向量的 Hybrid Dueling Double DQN。它们覆盖了从小型表格到神经网络、从离散描述到连续描述和空间输入的几种路线。

将两个目录去重后，所有有效候选可以放在同一张表里理解。这里的 R4 默认指含 idle 惩罚的版本。

| 候选组合 | 平均金币 / 50 | 全收集率 | 平均局步数 | 在研究主线中的作用 |
|---|---:|---:|---:|---|
| Continuous Double DQN + v1 + R2 | 49.52 | 86% | 167.43 | 当前最强导航参考，作为后续改进载体 |
| Double Q + compact + R4 | 47.77 | 75% | 190.50 | 紧凑表格路线的强候选 |
| Q-learning + discrete-q-v2 + R4 idle | 47.44 | 60% | 232.58 | 检查等待惩罚后的表现 |
| Double Q + compact + R3 | 45.77 | 71% | 201.89 | 势能塑形及 R4 比较的参考 |
| Q-learning + discrete-q-v2 + R4 旧版 | 44.70 | 31% | 312.57 | 暴露长等待问题的对照记录 |
| DQN + discrete-q-v2 + R4 | 40.66 | 29% | 318.75 | 暴露往返循环与完成率不足 |
| Hybrid Dueling Double DQN + hybrid-v1 + R2 | 2.05 | 0% | 400.00 | 本次复杂模型尝试的失败记录 |

这组探索表明，当前值得优先投入的组合是连续特征 Double DQN，同时保留紧凑 Double Q 作为较简单的对照。Hybrid 在本次训练下没有体现收益，离散 DQN 也没有超过表格候选。因此，现阶段继续增加网络复杂度缺乏实测支持。

这一判断选择的是“模型、表示与训练设置的组合”，并不能把 49.52 金币单独归功于 Double DQN 算法：各组合的 reward、特征和训练预算并不完全一致。两个 R2 的 Q-learning/DQN 历史模型还因特征版本不匹配而未成功评估，因此也不能宣称已经完成 R2 与 R4 的全面比较。

### 1.3 第二条探索线：平均得分不错，为什么仍然经常收不完

跨模型看结果后，出现了一个共同现象：模型可以收集很多金币，却仍在部分局中长时间等待或来回移动。例如旧 R4 Q-learning 平均有 44.70 个金币，但全收集率仅 31%，平均需要 312.57 步；DQN 平均 40.66 个金币，全收集率仅 29%。问题因此从是否获得奖励，进一步具体化为能否持续推进并结束任务。

奖励设计围绕这个问题逐渐细化。R2 提供真实事件奖励和每步代价；R3 增加状态势能差，为移动过程提供更密集的信号；R4 再增加对无进展往返的惩罚，并在后续版本加入连续安全等待惩罚。其基本假设是：明确给无效行为增加代价，可能帮助价值学习摆脱停滞。

已有结果对这个假设提供了部分支持。Q-learning 加入 idle 后，全收集率从 31% 提高到 60%，长等待率从 58% 降到 19%；Double Q 从 R3 到含 idle 的 R4，全收集率从 71% 提高到 75%，长等待率从 29% 降到 0%。这说明奖励塑形是值得继续研究的方向。

但另一半证据同样关键：Q-learning 的长乒乓率从 11% 升到 21%，Double Q 从 0% 升到 25%。这些比率不能证明惩罚直接造成了行为转移，却表明减少等待后仍可能存在移动循环。下一步需要判断动作是否带来真实进展，而不能把“动起来”本身当作成功。

### 1.4 两条探索线汇合：在较强模型上改进循环判断与历史信息

Continuous Double DQN + R2 已经达到 49.52 金币和 86% 全收集率，但仍有 14% 的局未完成收集；长等待和长乒乓也没有消失。因此，一个合理的后续选择是保留这条表现较好的模型路线，把研究重点转向残余循环问题。

循环具有历史依赖：同一个位置和当前棋盘，可能是首次经过，也可能是刚刚从相邻格走回来。当前目标也可能已经改变；为了转向新目标而回头，与围绕同一目标反复折返并不相同。如果奖励依赖这些区别，模型的输入也应提供相应信息。

由此形成配套方案：`continuous-v2` 在 v1 的 70 维基础上增加 14 维历史相关描述，包含前一动作、目标是否延续和各动作是否返回上一位置；R5 在 R3 基础上只对满足明确条件的循环与可避免 WAIT 施加惩罚。历史特征让相关差别更可观测，条件奖励则让训练信号更贴近要解决的行为问题。它们仍然让模型学习动作价值，不直接输出推荐动作。

这是一项待验证的假设：**在具备相关历史信息的连续特征 Double DQN 上，条件式惩罚能否进一步提高全收集率，并减少停滞，而不明显损害正常导航效率。** 两个目录提供了提出这一假设的依据，尚未提供证明 R5 有效的结果。

### 1.5 下一轮为什么要从探索性筛选转向配对实验

前面的实验帮助缩小了问题范围，但包含特征、reward 和实际训练预算的共同变化。下一轮应固定 `continuous-v2 + Double DQN`，从零训练 R3 和 R5 两个分支，统一初始化、训练 seed、探索计划、预算与评估条件，主要考察条件惩罚的增量价值。

旧的 `continuous-v1 + R2` 结果保留为历史性能参考；新实验内部的 `v2 + R3` 才是 `v2 + R5` 的直接对照。如果还要进一步回答“v2 历史信息本身有没有帮助”，需要另外设计固定算法和 reward 的 v1/v2 特征对照，不能由 R3/R5 比较代替。

研究是否推进，以全收集率、平均金币及局步数的改善为主，并检查循环/WAIT 诊断是否与之吻合。若只是惩罚触发变少而全收集率没有提高，说明目标行为或指标仍需调整；若收益在不同训练 seed 下不稳定，则需要记录这种不稳定性，再决定是否进入炸箱和对战阶段。

## 2. 实验口径与数据边界

| 项目 | 本批实际条件 |
|---|---|
| 任务 | Task 1 / `coin_navigation` |
| 场景 | `coin-heaven`，50 个金币，无箱子、无对手 |
| 动作 | 物理合法动作过滤；课程设置 `BOMB=false`；保留 WAIT |
| 评估 | 冻结 checkpoint，关闭探索；每组 seeds 10001–10005，每 seed 20 局 |
| 有效评估量 | 每个完整组 100 局；10 个完整组共 1000 条逐局记录 |
| 独立候选 | 去除同 checkpoint 重评后，7 个有有效结果的候选；另外 2 个候选评估启动失败 |
| 训练随机种子 | 所有引用的训练记录均为 seed 11 |
| 终止 | 收集完金币或达到最多 400 步 |
| 正式得分 | 本任务中等于收集金币数；训练 reward 与正式得分不是同一指标 |

5 个评估 seed 反映的是固定 checkpoint 在不同环境序列上的表现，不能代替 5 个训练 seed。训练本身的随机性尚未通过多次独立训练衡量。

结果表以原 summary 的 `AVERAGE` 行为入口，并用逐局记录重新核对金币、全收集数、平均步数和循环标记。CSV 中 5 个 seed 行后另有一个 `AVERAGE` 行，不能把它作为第 6 个 seed 再累计，否则会把每组 100 局误算成 200 局。

长等待率和长乒乓率表示出现相应长循环标记的局数比例，旧评估记录采用 10 步阈值；两者可以在同一局发生，也可以在最终完成收集的局中发生，不能相加作为失败率。WAIT 动作占比则以所有动作作为分母。详细导航诊断未在本批大多数记录中启用，因此空白或默认零值不能解释为“没有条件循环”。

## 3. 方法细节：各路线与 reward 定义

### 3.1 先建立可比较的学习与表示路线

初始方案以 Q-learning 和 DQN 为核心：从游戏状态提取客观特征，再由模型在合法动作中学习选择。随后拓展为紧凑 Double Q、连续特征 Double DQN 和 Hybrid Dueling Double DQN，用于观察表示方式及价值学习结构对导航的影响。

| 路线 | 本批历史特征 | 设计意图 | 实验中需要注意的变量 |
|---|---|---|---|
| Q-learning | R2 使用 `discrete-v1`；R4 使用 `discrete-q-v2` | 用表格建立易解释基线；v2 增加距离分桶和前一移动等信息 | R2 到 R4 同时改变特征与 reward |
| DQN | R2 使用 `discrete-v1`；R4 使用 `discrete-q-v2` | 用神经网络学习离散特征的动作价值 | 不能直接把差异归因于 reward |
| Double Q | `discrete-compact-v1` | 以紧凑状态和双 Q 表探索较低复杂度的方案 | R3/R4 使用相同特征，但实际训练预算不同 |
| Continuous Double DQN | `continuous-v1`，70 维；128×128 MLP | 用更丰富的连续描述与 Double DQN 进行导航 | 本批不是当前 `continuous-v2` |
| Hybrid Dueling Double DQN | `hybrid-v1`，12×17×17 棋盘与 70 维向量 | 融合空间输入和结构化描述 | 更高训练成本；本次训练有错误状态 |

以上是各路线的设计动机，不是已经证明的算法优势。当前候选同时涉及不同特征、reward、网络和训练时长，是探索性筛选，还不是严格的单变量消融。仓库虽已包含 CNN Agent，本次两个目录没有它的有效结果。

### 3.2 从事件奖励到导航塑形

R2 作为事件奖励基础，参数为：金币 +3、发现金币 +0.25、炸箱 +0.1、击杀 +5、自杀 −7、被杀 −5、存活 +0.25、非法动作 −0.2、每步 −0.01。死亡事件按实现去重。Task 1 禁炸弹且没有对手，部分参数不会产生区分作用。

R3 在 R2 基础上增加状态势能差 `0.95 × Φ(s') − Φ(s)`，金币、箱子、安全势能权重分别为 0.5、0.25、0.25。目的在于让真实事件之间也有学习信号，使导航进展更容易被价值学习捕获。

R4 在 R3 上加入往返惩罚 −0.08，后来又加入 idle 惩罚：满足安全且存在目标等条件的连续 WAIT，从第二步开始额外扣 −0.04，递增到最多 −0.12。当前实现还检查往返期间无金币收集、距离不改善等条件，因此不应把它描述为“所有反向移动都处罚”。

### 3.3 R4 名称与历史版本的纠正

当前注册表只有一个 `r4_anti_oscillation`，并且已包含 idle 惩罚；没有独立注册的 `r4_idle`。但旧训练和新训练沿用了相同的 reward ID：

| 历史训练目录 | 训练记录中的 R4 内容 | 本文称呼 |
|---|---|---|
| `q_learning_r4_t1_train` | 无 `idle_penalty_step` / `idle_penalty_cap` | R4 旧版，无 idle |
| `q_learning_r4_idle_t1_train` | idle step −0.04、cap 3 | R4 含 idle |
| `dqn_r4_t1_train` | 已含 idle | R4 含 idle |
| `double_q_r4_t1_train` | 已含 idle | R4 含 idle |

判定依据是训练 metadata 的完整 `rewards`，以及存在时的 `checkpoint_reward_contract.reward_spec`，不能只看运行名或评估顶层的 reward 参数。旧 Q-learning checkpoint 的评估顶层参数已经包含当前 idle 定义，但 checkpoint 嵌入的训练定义没有；冻结评估也不会因为加载了新 reward 配置而重新学习。

因此，“目录名没有 idle”不等于“训练时没有 idle”。后续应为改变行为的 reward 定义使用新 ID，或至少同时保存完整参数和源码身份，避免同名异义。

### 5.1 R2 两次评估失败

`dqn_r2_t1_eval` 和 `q_learning_r2_t1_eval` 的逐局文件均为 0 行，状态为 error。错误为：

```text
incompatible feature version/ID 'discrete-v1'; expected 'discrete-q-v2'
```

对应训练记录确实使用 `discrete-v1`。这说明评估配置与历史 checkpoint 不匹配，不说明 R2 模型性能差。补评时需显式固定历史 feature ID，检查源码兼容性并使用新输出目录。即使补评成功，R2/discrete-v1 与 R4/discrete-q-v2 的差异仍同时包含特征和 reward 两项变化。

### 5.2 Hybrid 的有效坏结果与流程错误

Hybrid 已产生可加载 checkpoint，冻结评估完成 100 局；2.05 金币和 89% 长乒乓率是有效的性能记录。同时，训练 metadata 记录 `ModuleNotFoundError: No module named 'matplotlib.backends.backend_agg'`，training.csv 留有 300 局。该错误指向绘图依赖，需要结合日志定位发生阶段；不能据此断言是模型计算崩溃，也不能把整个训练流程标为正常完成。

训练时间戳跨度约 20 小时，而 Continuous Double DQN 约 117 分钟。它们只反映本次运行的墙钟跨度，受环境、并发及错误影响，不能当作公平硬件速度基准。当前 Hybrid checkpoint 性能很差，但尚不能据此否定 Hybrid 架构本身。

## 6. 结果如何支持下一步判断

### 6.1 Continuous Double DQN 是当前导航基线

它在平均金币、全收集率和平均局步数上均优于本批其他候选，但仍有 14% 的局未收集完，且有长等待/乒乓现象。下一步可优先检查这些失败局的最后几枚金币、目标切换和路径选择。其较好表现不能单独归因为 Double DQN 或连续特征，因为未固定其余变量进行消融。

### 6.2 Q-learning 加入 idle 后有一致改善，但因果结论仍需控制实验

在 `runs/2` 的相同评估 seeds 上，含 idle 版本相对旧版：平均金币增加 2.74（44.70 → 47.44），全收集率增加 29 个百分点（31% → 60%），平均局步数减少 79.99（312.57 → 232.58），长等待率从 58% 降至 19%，WAIT 动作占比从 56.51% 降至 25.00%。5 个环境 seed 的平均金币均提高。

这些结果与“idle 惩罚缓解长时间原地等待”的假设一致。不过训练局数从 498 增至 564，动作步数和源码时间点也不同，不能写成 idle 惩罚的纯因果增益。长乒乓率还从 11% 增至 21%，说明只减少 WAIT 不保证导航完成。

### 6.3 Double Q 的 R4 改善了平均表现，仍留下循环问题

R4 相对 R3 平均金币增加 2.00，全收集率增加 4 个百分点，平均局步数减少 11.39。5 个评估 seed 中 4 个平均金币提高。长等待率从 29% 降至 0%，长乒乓率从 0% 增至 25%。这是失败类型变化的证据，尚不能仅凭这些比率认定具体 reward 项导致了行为转移。

### 6.4 DQN 与 Hybrid 的重点是行为和学习诊断

离散 DQN R4 平均 40.66 金币，但只有 29% 的局完成收集，57% 出现长乒乓；Hybrid 平均仅 2.05 金币。应检查循环状态下各动作的 Q 值、状态表示、目标切换和探索轨迹，再判断是否需要增加训练预算或改变模型。

### 6.5 计时与生存指标的解释

完整组汇总记录的 act timeout 均为 0，最大 act 耗时最高约 39 ms。它们支持“本次机器上的 Task 1 推理未触及 0.5 秒限制”，还不是正式 CPU 环境与对战场景验收。

Task 1 没有炸弹和对手，存活率及单人第一名比例几乎不提供选模区分。主要关注金币、全收集率、完成效率和行为失败。不要用单人胜率宣称对战能力。

## 7. 已形成的新方案：R3 与 R5 配对实验

目前仓库已有实验规格与配置，见 [conditional-loop spec](../.scratch/task1-conditional-loop-reward/spec.md)。该记录说明实现、配置与 smoke 已完成；本文范围的两个归档目录里没有 R5 的正式长训练结果。

思路是保留 R3 的事件奖励与势能，只对有明确条件的无效行为增加惩罚，同时用 `continuous-v2` 提供相关历史信息：

- 条件循环 −0.08：当前位置在本步死亡判定时刻安全；存在确定性的最近可达金币；目标与上一决策相同；执行动作后返回上一决策的位置。
- 可避免 WAIT −0.04：原地在未来 t=1、t=2 安全，并存在物理合法、t=1 安全且能缩短同一目标 BFS 距离的移动。

这两项不叠加旧 R4 的惩罚。无目标、目标变化或有危险等情况按各自条件豁免。设计意图是把“没有必要的循环/等待”与“场景允许或需要的动作”区分开，实际收益仍需评估。

| 固定项 | 两分支共同设置 |
|---|---|
| 算法与特征 | `double_dqn` + `continuous-v2` |
| 训练 seed / 预算 | seed 11，1000 局，关闭早停 |
| 设备 | CPU |
| 探索 | epsilon 1.0 → 0.05，80,000 action steps 线性衰减 |
| 评估 | seeds 10001–10005，各 20 局，开启导航诊断 |
| 唯一配置差异 | `r3_potential` 与 `r5_conditional_loop` 的 reward ID/version |

配置：[R3 baseline](../experiments/configs/task1_ddqn_continuous_r3_baseline.json)、[R5 conditional loop](../experiments/configs/task1_ddqn_continuous_r5_conditional_loop.json)。

这份探索计划在 80,000 action steps 时达到 epsilon 0.05。两分支必须使用相同计划，并在 metadata、checkpoint 和训练 CSV 中记录一致的实际值。

新配置的评估 seeds 与旧批次并不完全相同，且特征从 continuous-v1 改为 continuous-v2，因此不能把新 R5 与旧 49.52 金币结果的差值直接解释成 reward 收益。主要比较应是新方案内部的 R5 对 R3。

## 8. 建议的后续实验顺序

1. **补齐记录与兼容性。** 给历史 R4 标清是否含 idle；为两个 R2 checkpoint 准备与 `discrete-v1` 匹配的评估配置；检查 Hybrid 绘图错误。保留原始错误目录。
2. **运行 R3/R5 配对训练。** 先确定探索衰减预算，两分支从零开始，固定初始化、训练 seed、模型、特征、训练预算和评估条件。以全收集率和平均金币为主要指标，同时报告局步数、WAIT 占比、循环率和各惩罚触发/豁免计数。
3. **验证训练稳定性。** 若 seed 11 显示改善，再用额外训练 seeds（例如 22、33）重复。按环境 seed 配对评估，用现有 `compare_evaluations.py` 检查配对完整性、均值差和区间；训练 seed 间波动另行报告。
4. **检查失败局。** 对仍然耗尽 400 步的局，记录剩余金币、当前位置、上一位置、目标切换、危险条件和 Q 值。检查惩罚是否触发、是否出现替代循环，以及特征是否区分了需要不同动作的状态。
5. **回到后续任务。** 将导航候选用于 Task 2 炸箱与逃生，再到弱对手和强对手评估；同时补课程基线。升级 reward 时检查必要等待是否被误罚，升级任务时复测已有能力。

上述顺序是根据现有失败模式提出的后续方案，不代表这些实验已经执行。若不改善，也记录差值、训练预算和失败行为，避免以训练 reward 上升替代实际任务收益。

## 9. 复现与后续记录模板

历史复现必须先查看目标 seed 的 metadata，使用其中的 feature schema、完整 reward 参数、checkpoint 和源码身份。当前默认配置持续演变，直接重跑旧文件名不保证复现旧实验。对于重复记录，应先识别 checkpoint 和 seed，避免重复计数。

每次新实验建议追加以下信息：

| 字段 | 要记录的内容 |
|---|---|
| 问题与假设 | 观察到什么行为，预期哪项改变能改善它 |
| 唯一变量及固定条件 | 算法、特征、reward 完整参数、初始化、种子、预算、早停、探索 |
| 数据身份 | train/eval run_id、checkpoint、source commit/hash、配置 hash |
| 完成情况 | 实际局数、action steps、epsilon、错误与中断 |
| 主要结果 | 金币、全收集率、局步数、seed 波动、配对差值 |
| 行为诊断 | 长等待、乒乓、条件循环、目标切换、WAIT 豁免、代表性回放 |
| 判断与决定 | 假设支持程度、仍存在的混杂因素、保留/调整/停止的理由 |
