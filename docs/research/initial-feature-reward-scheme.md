## 设计目标

初代方案用同一套状态信息比较 tabular Q-learning 和 DQN，尽量避免把“模型差异”与“特征差异”混在一起。主要目标是：

1. 用紧凑、确定性的状态表示降低训练样本需求。
2. 将物理合法性与策略安全性分开。
3. 在特征中提供金币导航、放弹逃生和基础对手信息。
4. 奖励以官方目标事件为主，只加入少量时间、炸箱和非法动作 shaping。
5. 不由特征或奖励代码直接输出手写的最佳动作，最终策略仍由训练产生。

## 特征版本 `discrete-v1`（旧名 `v1`）

### 形式接口

旧兼容入口 `features.py::extract_features(game_state)` 返回
`DiscreteFeatures(feature_id, state_key, vector, legal_mask, action_transform)`；其中后三个核心字段保持原值：

- `state_key`：14 个离散字段，作为 Q-learning 的 Q-table key。
- `vector`：由同一批字段 one-hot 展开的 40 维 `float32` 向量，作为 DQN 输入。
- `legal_mask`：按 `UP, RIGHT, DOWN, LEFT, WAIT, BOMB` 排列的物理合法动作布尔数组。

离散字段类别数为：

```text
(3, 3, 3, 3, 3, 3, 3, 2, 2, 2, 2, 5, 4, 2)
```

理论组合数为 `1,399,680`，one-hot 后维度为 `40`。

### 字段定义

| 索引 | 类别数 | 初代语义 |
|---:|---:|---|
| 0–3 | 3 | `UP/RIGHT/DOWN/LEFT` 分别为：非法、合法但无完整逃生路线、合法且有完整逃生路线 |
| 4 | 3 | 当前格安全、下一步危险、之后危险 |
| 5 | 3 | 不能放弹、能放但无法逃生、能放且可逃生 |
| 6 | 3 | 假设当前放弹可炸到 0、1、2 个及以上箱子 |
| 7–10 | 2 | 四个移动方向是否缩短到最近可达金币的 BFS 距离 |
| 11 | 5 | 无对手，或最近对手在上、右、下、左主导方向 |
| 12 | 4 | 无对手、Manhattan 距离 1、距离 2–4、距离大于 4 |
| 13 | 2 | 假设在当前格放弹，爆炸范围是否覆盖任意对手 |

### 危险与逃生模型

预测时域为：

```text
BOMB_TIMER + EXPLOSION_TIMER + 1
```

危险图包含当前爆炸、现有炸弹和可选的假设炸弹。逃生搜索在时间展开的可通行图中执行，考虑墙、箱子、炸弹占位、其他 Agent、箱子被炸毁后的可通行性以及每个未来时间步的危险格。

`legal_mask` 只表达物理合法性，不会删除危险但可执行的动作。这使模型能学习安全性的价值，同时保证不会在下一状态的最大 Q 值中使用物理非法动作。

## 奖励版本 `r1`

| 条件或事件 | 数值 | 设计意图 |
|---|---:|---|
| 每条完成转移 | `-0.01` | 轻度惩罚耗时，鼓励更快完成目标 |
| `COIN_COLLECTED` | `+1.0` | 与官方金币得分目标一致 |
| `KILLED_OPPONENT` | `+5.0` | 与课程规定的击杀价值一致 |
| `CRATE_DESTROYED` | `+0.2` | 在隐藏金币阶段提供更稠密的中间反馈 |
| `INVALID_ACTION` | `-0.1` | 抑制无效动作 |
| `KILLED_SELF` 或 `GOT_KILLED` | 合计 `-10.0` | 强烈惩罚死亡，同一次死亡只计一次 |

`BOMB_DROPPED`、`COIN_FOUND` 和 `SURVIVED_ROUND` 没有单独奖励。同一转移中的金币、击杀和炸箱事件按出现次数累计，死亡事件则布尔去重。

### 消融版本 `r1_no_crate`

`r1_no_crate` 只将 `CRATE_DESTROYED` 奖励从 `+0.2` 改为 `0.0`，其他数值和语义与 `r1` 相同。该变体用于检验炸箱 shaping 是否真正改善正式游戏指标，而不只是提高训练奖励。

## 属性和已知限制

- **手工表示**：BFS、危险时序、距离分箱和爆炸覆盖都是人工指定；DQN 不会从原始棋盘学习这些表示。
- **非手写策略**：特征不返回唯一最佳动作，安全、金币、炸箱和对手信息的权衡由 Q-learning 或 DQN 从经验中学习。
- **状态混叠**：压缩丢失了精确坐标、多个金币/对手的完整布局、分数、回合进度和更长期战术信息。
- **对手模型简化**：最近对手按 Manhattan 距离选择，方向忽略墙和箱子，时间搜索将对手视为固定障碍。
- **隐藏金币**：金币 BFS 只能使用当前可见且可达的金币；箱子后的未知金币主要依赖炸箱特征和奖励探索。
- **奖励假设**：死亡惩罚和炸箱奖励的相对尺度可能导致过度保守或刷箱子，必须用真实得分、金币、击杀、存活率和非法动作等正式指标验证。

## 实验与演进规则

1. Q-learning 与 DQN 的主比较应使用同一 `feature_version` 和 `reward_version`。
2. 每次只修改一个主因素，例如使用 `r1_no_crate` 隔离炸箱奖励的影响。
3. 特征字段、类别数、动作顺序或语义变化时，创建新特征版本，并拒绝加载旧版本参数。
4. 任何奖励数值或奖励语义变化都创建新奖励版本。
5. 运行 metadata 和 checkpoint 必须同时保存版本号与完整奖励表；最终模型选择必须依据系统实验，不能只比较训练奖励。

后续公共 Feature System 增加的 `discrete-compact-v1`、`continuous-v1`、`board-v1` 和 `hybrid-v1` 不属于本初代历史方案，也不会回写改变这里冻结的 14/40 维语义。它们的现行契约见 `agent_code/team_agent/feature_system/README.md`。
