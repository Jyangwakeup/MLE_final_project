# 第二批工程测试：对手恢复放弹能力导致逃生塌缩

执行源码c8c9770，世界24200–24299。Task1/2各100局完成；Task3完成66局，在世界24266第184步因avoidable_escape_collapse停止；Task4完成42局后由控制器取消。失败及部分产物全部保留，不能称为第二批通过。独立轨迹审计在同一步检出own_bomb_pending与physical_fallback同时为True，说明先前合成诊断漏洞确实在本次较晚轨迹出现；原始reason仍保持不变。

第181步放弹有证明，第182步DOWN、第183步RIGHT均获准，第184步无七步安全动作。第182步的真实下一状态与枚举中的DOWN/LEFT场景仅在对手bombs_left不同：框架恢复为True，模拟状态仍为False；抽象未来的armed_names又永久排除了这个对手。单纯延长旧证明到八步仍接受DOWN，而让抽象未来覆盖对手恢复能力并延长到六步以上会拒绝DOWN、保留UP/WAIT。第183步已有对手可放弹，四步证明仍接受RIGHT/WAIT，五步以上均拒绝：另一原因是证明截止早于新对手炸弹的爆炸。

因此拟新增版本：第一步动作仍遵守当前真实容量；后续抽象允许所有存活对手恢复放弹能力，证明时域至少覆盖现有七步安全观察窗口和自身完整危险期。公开状态缺少炸弹所有权，恢复时间采用保守上界，不伪称能够准确重建隐藏所有权。旧版本、400ms搜索预算、动作由Q值排序、奖励、特征、父权重与所有准入门槛保留；先做真实现场回归及性能测试，再进行新的冻结工程评估，不续接失败运行，不训练或宣告Task4合格。
