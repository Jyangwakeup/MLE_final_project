# Bomberman 游戏策略与 Task 1–4 训练课程

> 更新日期：2026-09-16  
> 适用项目：Machine Learning Essentials 2026 Final Project  
> 文档性质：团队训练与实验建议，不替代课程要求。课程公告与 MaMPF、原始
> `notes/final_project.pdf`、`PROJECT_REQUIREMENTS.md` 的优先级高于本文。

## 1. 目标与基本判断

正式游戏的直接得分为：

- 收集一枚金币：`+1`；
- 击杀一名对手：`+5`；
- 每局最多 400 步；
- 多局累计总分决定比赛结果。

因此，一次击杀的直接价值等于五枚金币。Classic 场景只有 9 枚金币，而一局最多有
3 名对手，所以金币提供稳定基础分，击杀提供主要的分差。死亡虽不直接扣正式分，却会
失去余下的收集和击杀机会。

局内策略的总原则是：

```text
先避免可证明的死亡
→ 稳定收集可达金币
→ 安全炸箱并打开地图
→ 利用地形和炸弹制造高概率击杀
```

最终选模必须使用冻结策略的真实游戏指标，而不能使用 shaped training reward：

```text
mean_score = mean(coins + 5 * kills)
```

## 2. 推荐局内策略

### 2.1 生存优先

每次决策应利用炸弹倒计时、爆炸范围、已有爆炸和时变障碍，预测未来约 7 步的危险。
对每个候选动作，至少分析：

- 动作后位置在 `t=1/2/3` 是否危险；
- 最早危险时刻；
- 能存活到预测窗口末端与否；
- 可到达安全区域的大小；
- 假设本步放弹后是否仍有逃生路径。

不要为了一枚金币或低概率攻击进入可证明必死的状态。攻击也应满足“自己有逃生路径”
这一前提。

### 2.2 金币导航

安全时选择最近的可达金币，使用考虑墙、箱子、炸弹和其他 Agent 的路径距离，而不是只用
曼哈顿距离。需要惩罚或诊断以下行为：

- 无必要的 `WAIT`；
- 两格往返；
- 长期循环；
- 频繁改变目标导致的低效移动。

### 2.3 安全炸箱

没有可见金币时，通过炸箱暴露隐藏金币并扩大通行空间。好的放弹状态应满足：

- 放弹后存在完整逃生路径；
- 能炸到至少一个箱子，优先覆盖多个箱子；
- 不在没有出口的深处放弹；
- 不反复炸空地；
- 地图已经足够开放时降低纯炸箱倾向。

炸箱没有正式得分，只是通向金币、空间和战术位置的中间目标，因此其训练奖励应远小于
金币和击杀奖励。

### 2.4 高概率击杀

强攻击策略不是简单地“朝对手移动并放弹”，而是压缩对手的时空逃生集合：

- 对手处于死胡同或狭窄通道；
- 墙、箱子、炸弹或其他 Agent 封住出口；
- 已有炸弹封锁一个方向，新炸弹封锁另一个方向；
- 对手正处于危险时间窗口；
- 自己放弹后仍能安全撤离。

最重要的攻击判断是：

```text
假设现在执行某动作或放弹：
1. 自己能否存活到 H=7？
2. 每个对手能否存活到 H=7？
3. 有多少对手没有完整逃生路径？
```

## 3. 当前 `continuous-v2` 已经包含的信息

当前 Task 2 胜者使用 84 维 `continuous-v2`。它已经读取对手、炸弹和爆炸状态，但大多
压缩成客观摘要，而不是把完整坐标和时空图直接输入 MLP。

### 3.1 对手信息

已有：

- 每个候选动作的 `opponent_distance_delta`；
- `reachable_opponent_exists`；
- 当前格放弹可覆盖的对手比例 `opponents_threatened`；
- 当前存活对手比例 `alive_opponents`。

缺少：

- 各个对手独立的时域危险；
- 各对手的安全出口数量；
- 假设放弹后各对手能否逃生；
- 多颗炸弹对对手形成的夹击；
- 对手受困程度。

### 3.2 炸弹时间和危险范围

已有危险预测读取 `game_state["bombs"]` 中的位置和 timer，并按当前框架语义使用：

```text
爆炸时刻 = timer + 1
```

预测同时考虑：

- 炸弹威力 3；
- 石墙阻挡；
- 当前实现中箱子不阻挡爆炸传播；
- `explosion_map` 的残留危险；
- 爆炸持续时间；
- 假设本步自己放置的新炸弹。

系统构造未来危险图 `danger[t, x, y]`。`continuous-v2` 对六个动作分别包含
`danger_t1/t2/t3`、`earliest_danger`、`safe_horizon`、`safe_area`，并包含放弹后的
`escape_after_bomb` 与 `safe_area_after_bomb`。

所以 Task 3 真正需要补充的不是基础炸弹信息，而是“以对手为中心的时域可逃性”。

## 4. Task 3 推荐新增的攻击特征

建议建立新的版本化 Feature ID，并从 Task 1 重新训练。新字段应描述可验证事实，不能直接
输出推荐动作：

- 各候选动作后的最近对手路径距离变化；
- 最近或最受威胁对手的 `danger_t1/t2/t3`；
- 对手可存活到 H=7 的比例；
- 对手安全出口或第二步可延续动作的比例；
- 假设自己放弹后，无法活到 H=7 的对手数量；
- 自己安全且至少一名对手受困；
- 多炸弹危险区是否压缩了对手的安全区域。

禁止加入：

- `best_action`；
- `recommended_bomb`；
- `best_attack_direction`；
- 任何综合人工评分后直接指定的动作。

## 5. `survival-mask` 的合规边界

课程明确要求 Agent 必须通过机器学习做决策，不能用一个直接确定“最佳动作”的特征或规则
绕过学习。`survival-mask` 不对安全动作排序，也不直接选择最高收益动作；它只排除有限时域
搜索中没有任何存活轨迹的动作，剩余动作仍由 Q 网络选择。因此它可以被论证为安全约束，
但正式推理中使用硬 mask 仍存在合规灰区。

风险由低到高大致为：

| 做法 | 合规风险 |
|---|---|
| 屏蔽物理非法动作 | 很低 |
| 将危险与可逃性作为网络特征 | 很低 |
| 用死亡惩罚训练 | 很低 |
| 训练探索时避免可证明必死动作 | 较低 |
| 正式推理时硬屏蔽预测必死动作 | 中等，需明确论证 |
| 搜索后只留下一个人工选择的动作 | 高 |
| 直接返回人工计算的最佳动作 | 明确不合规 |

正式实验至少保留：

- `physical-only`：只屏蔽物理非法动作；
- `survival-features + physical-only`：让模型学习安全；
- `survival-features + survival-mask/all`：测量安全层的额外收益。

记录 `safety_intervention_rate`、干预后平均剩余动作数和只剩一个动作的比例。如果 mask 经常
只留下一个动作，规则替代学习的风险会明显增加。最终是否提交硬 mask，应结合消融结果，
并在可能时向课程教师明确确认。

## 6. 全训练链的固定合同

若新增攻击特征改变输入维度，应先冻结 Feature、Reward、Safety、网络和评估合同，再开始一条
新的完整训练链：

```text
Task 1 cold start
  → Task 2 同 seed warm start
  → Task 3 同 seed warm start
  → Task 4 同 seed warm start
```

推荐三个独立 training seed：`11、22、33`。不同 seed 不得互相继承 checkpoint。

推荐四阶段保持同一个基础奖励版本：

| 事件 | 建议训练奖励 |
|---|---:|
| `COIN_COLLECTED` | `+3.0` |
| `KILLED_OPPONENT` | `+5.0` |
| `CRATE_DESTROYED` | `+0.2` |
| `KILLED_SELF` | `-20.0` |
| `GOT_KILLED` | `-10.0` |
| `INVALID_ACTION` | `-0.1` |
| 每条完成 transition | `-0.01` |

死亡事件同一步只惩罚一次。不要直接奖励普通放弹、接近对手或“炸弹覆盖到对手”。

## 7. Task 1：金币导航

### 设置

```text
scenario: coin-heaven
opponents: none
BOMB: disabled
initialization: cold start
```

### 学习目标

- 最短路径收集可见金币；
- 避免 WAIT、往返和长期循环；
- 验证历史特征、探索和冻结评估正确；
- 新增的对手和炸弹字段保持定义完整，在无对应对象时自然为零。

### 预算与停止

- 每个 seed 至少训练 300 局；
- 冻结 20 局评估平均分 `>=48/50`；
- 连续三次评估通过才停止；
- 最多约 1000 局，超过后优先诊断而不是继续堆预算。

### 验收

- 禁止执行 `BOMB`；
- 无效动作率 `<=1%`；
- 长 WAIT 和往返循环接近 0；
- 训练 reward 与冻结金币得分方向一致。

## 8. Task 2：炸箱、隐藏金币和逃生

### 设置

```text
scenario: classic
opponents: none
BOMB: enabled
initialization: same-seed Task 1 checkpoint
```

### 学习目标

- 只在存在逃生路径时放弹；
- 炸箱并收集隐藏金币；
- 避免空放、等待循环和自杀；
- 保留 Task 1 导航能力。

### 预算

- 每个 seed 至少 500 局；
- 至少约 150,000 个 Task 2 action steps；
- 未达标时增加到最多约 2000 局；
- 每 100–250 局进行冻结诊断。

### 晋级门槛

| 指标 | 门槛 |
|---|---:|
| 平均金币 | `>=6.0/9` |
| 零金币局率 | `<=5%` |
| 收齐 9 枚金币比例 | `>=10%` |
| 平均炸箱 | `>=60` |
| 每 100 步金币 | `>=1.5` |
| 自杀率 | `<=5%` |
| 零放弹局率 | `<=10%` |
| 放弹存活率 | `>=95%` |
| 长 WAIT 循环率 | `<=10%` |
| 长往返循环率 | `<=5%` |
| Task 1 得分保留率 | `>=90%` |

当前已登记的 `continuous-v2` Task 2 胜者约为 `7.25/9` 金币、`100.26` 个箱子、
`0%` 自杀和 `100%` 放弹存活，可作为不改变合同情况下的 Task 3 基线。

## 9. Task 3：攻击弱对手

### 设置

```text
scenario: classic
opponents: peaceful_agent + coin_collector_agent
initialization: same-seed qualified Task 2 checkpoint
```

### 学习目标

- 追踪可达对手；
- 在自己能逃生时放弹；
- 利用墙、箱子和已有炸弹压缩对手出口；
- 学会攻击移动目标；
- 保留金币、炸箱和自身逃生能力。

### 奖励实验

第一版只沿用真实击杀 `+5`。如果击杀长期学不出来，再开一个严格单因素分支，使用对手可逃
状态的势函数：

```text
r_attack = gamma * Phi(next_state) - Phi(state)
```

`Phi` 只能来自对手安全出口比例、可存活比例等状态事实。单步辅助量建议限制在约
`±0.05–0.2`，并且不能直接奖励“执行 BOMB”或“炸弹覆盖对手”。

### 预算

- 每个 seed 基础 1500 局；
- 每 250 局冻结评估；
- 如指标仍稳定改善，最多追加约 375 局。

### 晋级门槛

- 相对 Task 2 父模型，平均击杀增加 `>=0.1/局`，或第一率提高至少 5 个百分点；
- 真实平均分提高；
- 自杀率最好 `<=5%`，且不得明显恶化；
- 平均金币和 Task 1/2 能力保留率均 `>=90%`；
- 无超时，完整 `act` P95 `<50 ms`、最大值 `<500 ms`。

分别报告对 `peaceful_agent`、`coin_collector_agent` 和二者同时出现时的结果，避免汇总后无法
定位攻击失败类型。

## 10. Task 4：正式强对抗

### 设置

```text
scenario: classic
target opponents: 3 * rule_based_agent
initialization: same-seed qualified Task 3 checkpoint
```

### 分段课程

1. 前约 25%：1–2 个 `rule_based_agent`，其余为较弱对手，降低难度突变；
2. 中间约 50%：正式阵容 `3 * rule_based_agent`；
3. 最后约 25%：混合强对手和冻结的历史 checkpoint，改善泛化。

自我对弈应使用冻结历史 checkpoint，不让所有对手跟随在线模型同时更新。

### 预算

- 每个 seed 基础 3000 局；
- 每 250–500 局冻结评估；
- 未达标且仍在改善时最多追加约 750 局；
- 保留多个阶段 checkpoint，不默认最后一个就是最好。

### 晋级和选模

第一指标为对三个 `rule_based_agent` 的真实 `mean_score`。随后依次比较：

1. 平均击杀；
2. 独占第一率；
3. 生存率和自杀率；
4. 平均金币；
5. 无效动作和超时；
6. Task 1–3 能力保留率。

相对 Task 3 父模型，平均击杀应增加 `>=0.1`，或第一率提高至少 5 个百分点；真实平均分不能
下降，旧 Task 得分保留率应 `>=90%`。

## 11. 推荐实验矩阵

算力应集中到少量可解释比较：

| 链 | 模型 | Safety | 目的 |
|---|---|---|---|
| A | Double DQN | physical-only | 证明学习策略本身的能力 |
| B | Double DQN | survival-mask/all | 当前安全主线 |
| C | Rainbow-lite | survival-mask/all | 不同学习模型挑战者 |

所有链共享 Feature、Reward、训练 seeds、评估 seeds、阶段设置和预算。算力有限时先用 seed 11
开发筛选，淘汰明显失败方案后，再对两个胜出方案完成 `11/22/33` 三条独立训练链。

## 12. 最终评估流程

```text
开发评估
  → 三个 training seeds 完整完成 Task 1–4
  → 100 个主验证环境，对抗 3 * rule_based_agent
  → 先选模型族，再选该模型族内的单个 checkpoint
  → 锁定代码、配置和权重
  → 仅对唯一胜者运行一次保留的 20000–20099 最终测试
```

每个 training seed 先独立报告，再报告跨 training seed 的均值和样本标准差。同一 checkpoint
的 100 个环境 seed 不能写成 100 次独立训练。

## 13. 当前执行重点

当前 Task 2 能力已经足够强，继续主要优化炸箱数的边际价值很低。接下来的训练资源应集中在：

1. 对手时域逃生建模；
2. 自己安全前提下的受困与封路判断；
3. Task 3 的可靠击杀；
4. Task 4 强对手下的真实平均分；
5. `physical-only` 与 `survival-mask` 的合规和能力消融。
