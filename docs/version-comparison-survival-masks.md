# Mask 版本对比：生存约束的演进

## 1. 范围与基本定位

本文覆盖 `survival-mask-v1` 至 `survival-mask-v5`。mask 是 learner 外围的动作否决边界：先从物理合法动作出发，删除未通过某种生存证明的动作，再由学习到的 Q 值在剩余动作中排序。它不是规则策略，不推荐某个方向，也不直接改变 reward。

```text
物理合法动作
  └─ v1：存在一条 H=7 生存路径
      ├─ v2：己方炸弹期间保留接近最大逃逸面积的动作
      └─ v3：己方炸弹期间要求两条内部顶点不相交路径
          └─ v4：再要求通过所有建模的一步对手联合转移

v5：以 v1 为基础，但把己方炸弹完整危险期建模为反馈可控生存问题；
    它替代 v3/v4 的静态逐步证明，而不是简单在 v4 后再加一层。
```

## 2. 所有 mask 的共同点

- 输入首先是物理合法动作集合；mask 不会把碰墙、走入占用格或无资格放弹变成合法动作。
- 固定预测 horizon 为 7，顶层 fallback 固定为 `physical_q`。
- 支持 `off`、`exploration`、`all` 三种模式：关闭、只约束探索动作、约束探索与贪心/推理。
- mask 只做 veto，剩余动作仍由 Q 值排序；这保持“决策由训练学习”而非规则直接指定。
- 当基础安全集合为空时，返回全部物理合法动作并记录 no-safe-action fallback，而不是随机动作或假称已救援。
- 同一安全契约应一致用于探索、贪心行为、冻结推理、replay next mask 和 Double DQN bootstrap，否则训练目标与执行边界不一致。
- `allow_bomb=false` 时先从物理集合移除 BOMB，再做安全计算。
- 超时、fallback 和干预都必须单独记录；“最后活着”不能反推当时完成了安全证明。

## 3. 版本总览

| 版本 | 核心证明 | 主要解决的问题 | 失败后的退路 |
|---|---|---|---|
| v1 (`survival-mask-v1`) | 至少一条路径活过 H=7 | 立即或有限时域内可避免的死亡 | 无安全动作时回到 physical Q |
| v2 (`survival-mask-v2`) | v1 + 己方炸弹期逃逸面积 ≥ 最佳的指定比例 | 避免主动耗尽逃逸空间 | refinement 空则回 v1；v1 空才 physical Q |
| v3 (`survival-mask-v3`) | v1 + 两条内部顶点不相交的时空逃生路径 | 避免单一路径被自己后续动作封死 | robust 空则回 v1；v1 空才 physical Q |
| v4 (`survival-mask-v4`) | v3 + 所有建模的一步对手动作/放弹/执行顺序均通过 | 避免对手下一步堵路或放弹破坏静态证明 | opponent 层空回 v3，v3 空回 v1 |
| v5 (`survival-mask-v5`) | 完整己方炸弹危险期的反馈可控生存集；第一步精确、后续保守抽象 | 把责任前移到创造义务的 BOMB，并覆盖后续对手反应 | 义务中 robust 空回 v1并记 guarantee loss；搜索失败关闭证明 |

## 4. v1：有限时域可生存动作集合

对每个物理合法动作，v1 使用时间展开的危险和阻塞图检查：执行第一步后，是否至少存在一条后续动作序列能存活到 H=7。BOMB 使用“假设当前格新增己方炸弹”的危险图；移动与 WAIT 使用正常危险图。

通过的动作构成 survival mask。若至少一个通过，只允许这些动作；若没有任何动作通过，则返回物理合法集合，并标记 `physical_fallback=true`。这个 fallback 的含义是“没有被证明可活的选择”，绝不代表返回动作安全。

优点是成本低、适用于所有决策；局限是存在性证明只说明“有一条未来路线”，并不保证 learner 后续会沿该路线，也未考虑对手下一步主动封路。

## 5. v2：己方炸弹期间保持逃逸面积

v2 先完整运行 v1。只有在 v1 非空且 `own_bomb_pending=true` 时，才读取每个 v1 动作在 horizon 末端的 `escape_area`，保留面积至少达到当前最佳动作 `escape_area_fraction` 的动作。仓库契约要求比例在 (0,1]；预注册实验采用 0.75。

若面积筛选意外为空，v2 回到完整 v1 集合并记录 margin fallback；若 v1 本身为空，才回 physical Q。它避免因单步 Q 偏好连续选择空间越来越小的动作。

局限是“面积大”不等于存在结构独立的逃生路线；大量终点也可能共享同一个瓶颈。因此 v2 只在预注册安全失败后启用，而没有默认替换 v1。

## 6. v3：两条内部顶点不相交路线

v3 的新增契约固定为 `required_independent_routes=2`，robust fallback 为 v1。

- 放弹前：只对 BOMB 做两路证明。如果 BOMB 在 v1 中安全，但假设放弹后少于两条独立时空路径，并且存在 v1-safe 的非 BOMB 动作，则 veto BOMB。
- 己方炸弹义务期间：对 v1 中的候选移动/W​​AIT 计算独立路线数，只保留至少两条路线的动作。
- 若义务期间没有动作满足两路要求，则退回完整 v1 集合，并记录 `robust_fallback`。

“内部顶点不相交”比单纯终点数量更强，因为两条路线不能共享相同中间瓶颈。它仍只是一组允许动作，不会替 learner 选择具体逃跑方向。

局限是逐步静态检查：某一步有两路，不代表对手的联合行动后仍有两路；也可能较晚才处罚最后一个逃生动作，却已经在更早的放弹决策创造了无法保证的义务。

## 7. v4：加入对手一步联合转移鲁棒性

v4 继承 v3 的两路检查，并固定以下对手模型：对手动作空间为所有物理合法动作，允许对手放弹，枚举所有执行顺序，对手转移 horizon 为 1，每个情景至少保留一条路线；对手层失败时回退 v3。

对于候选动作，系统模拟所有建模的对手动作组合及允许的执行顺序，包括位置、炸弹、爆炸、箱子破坏和死亡后的新状态。候选只有在所有情景均能继续生存时才通过。诊断会记录情景总数、通过数、首个失败的对手动作 profile 和执行顺序。

放弹前仍将证明责任放在 BOMB：若 BOMB 未通过且有安全非 BOMB 替代，则否决。己方炸弹期间则从 v3 集合中进一步筛选。

局限是只精确看一步对手转移，之后仍使用静态 continuation；完整未来联合树会组合爆炸并超过内部预算。

## 8. v5：完整危险期的反馈可控生存

v5 不再要求“两条静态路线”，而是问一个更直接的问题：从当前候选动作开始，在己方炸弹和余焰完全消失前，是否存在一个反馈策略，使 Agent 面对每个建模的对手转移都能继续存活。后续动作可以根据新观察状态改变，不要求预先固定一条路线。

实现分两段：

1. 第一轮联合转移精确建模所有对手物理合法动作、对手放弹、全部执行顺序及官方世界更新。
2. 后续历史不展开指数级完整树，而用对手可达占用和炸弹危险的保守并集，再对 learner 做向后可达性计算。

这种抽象可能保守地拒绝实际能活的动作，但设计目标是不因选择了某条“有利的对手未来”而错误批准。

### 放弹前

v5 只对 BOMB 候选运行完整可控生存证明。若 BOMB 未被证明，并且存在 v1-safe 非 BOMB 动作，就拒绝 BOMB。这样把安全责任放到“创造未来逃逸义务”的决策上。

### 己方炸弹义务期间

对所有 v1-safe 非 BOMB 动作求可控生存集。若集合非空，只允许其中动作；若为空，退回 v1，但记录 `robust_guarantee_loss=true` 和 opponent/robust fallback。这个状态是安全门失败信号，即使本局最终没有死亡也不能算证明成功。

### 预算与 fail-closed

配置固定内部搜索预算 400 ms，危险区间为 `own_bomb_and_lingering`。搜索超时或无法完成时，候选不能被标记为 robust，并记录 `robust_search_timed_out` 与评估状态数。实验工程门进一步要求 P95、最大 act 时延和超时数达标；“因为超时而拒绝了一个危险动作”也不能算安全证明成功。

### 与 v3/v4 的本质差别

v3 证明路线冗余，v4 在此基础上加入一步对手扰动；v5 证明的是整个己方炸弹危险期内的反馈可控性。v5 因此是模型重构，不是简单把 required routes 从 2 改为更大数字。

## 9. mode、fallback 与诊断字段

### mode

- `off`：返回物理合法集合；版本号即便写 v1/v5，也不产生安全 veto。
- `exploration`：只约束随机探索，贪心/冻结决策仍用物理集合。
- `all`：探索、训练贪心和正式推理均启用；正式安全实验通常使用此模式。

### 三类不可混淆的失败

- `physical_fallback`：v1 集合为空，没有 horizon-survivable 动作。
- `robust_fallback` / opponent fallback：基础 v1 非空，但更强的 v3/v4 筛选为空。
- `robust_guarantee_loss`：v5 的主动己方炸弹义务期间，可控生存集为空，只能退回 v1。

这些都不等于死亡。反过来，没有死亡也不等于没有 guarantee loss。

### 主要可审计信息

`SafetyDecision` 保存最终 mask、v1 mask、路线数、逃逸 slack、对手情景/通过数、首个失败 profile/顺序、是否超时、评估状态数等。它们用于解释 veto 和实验门，不应该作为隐藏的规则动作推荐。

## 10. 版本选择和实验公平性

- 比较 mask 时应冻结 v、r、模型权重、对手、seed 和 n-step，只改变安全版本；否则无法把死亡率变化归因于 mask。
- 安全指标至少包括 avoidable fatal action、自杀、放弹局比例、干预率、fallback、v5 guarantee loss、超时和 act 延迟。还必须检查金币/箱子/击杀保留，防止通过“一直不放弹”虚假提升安全。
- v5 的保守性可能降低战斗能力，因此冻结准入包含资源/战斗保留门和零放弹局门。
- 不能把 mask 描述成“safe policy”。v1 只给有限时域存在性，v3/v4/v5 也只覆盖各自建模假设。
- 官方环境没有连锁爆炸；安全模型不得自行加入 chain reaction，否则证明针对的不是实际游戏。
